# 健康管理アプリ（パーソナル食事・健康・筋トレ・サプリ管理）

本人専用の健康管理アプリ。医療診断は行わず、事実の整理・提案・必要時の受診促しに徹する。
体重・体組成の記録を中核機能とし、食事・間食・飲酒・筋トレ・サプリ・健診データを一元管理する。

詳細な要件・画面設計・データ構造・AI判定ルール・医療安全ルールは元の引継ぎ資料を参照。

## 同梱アプリ

このリポジトリは Vite のマルチページ構成で、3つのフロントエンドをビルドする。

| ページ | 内容 |
| --- | --- |
| `index.html` | 健康管理アプリ（食事・健診・筋トレ・サプリ・体重） |
| `mortgage.html` | 住宅ローン 金利シナリオ・シミュレーター |
| `fax.html` | FAX送付状 かんたん作成 |

開発サーバー起動後は `http://localhost:3000/`（健康管理）、`http://localhost:3000/mortgage.html`（シミュレーター）、`http://localhost:3000/fax.html`（FAX送付状）でそれぞれ開ける。
公開後は `https://<ユーザー名>.github.io/<リポジトリ名>/mortgage.html`。

### 住宅ローン 金利シナリオ・シミュレーター

変動金利が段階的に上昇した場合に、月々返済額・残高・総返済額がどう変わるかを試算し、
**金利と総返済額の相関**をグラフで確認するための単体アプリ（Firebase 非依存・入力値はサーバーに送らない）。

- 借入額・返済期間・当初金利・見直し間隔・上昇幅・上限金利をその場で変更して再計算
- 「金利と総返済額の相関」グラフは、X軸を「見直しごとの上昇幅」と「全期間固定金利」で切り替え可能
- 累計利息 / 残高の推移、月々返済額の階段状の推移、区間ごとの内訳表
- 125%ルール（返済額の上昇を直前の1.25倍までに抑える）を有効にすると、未払利息と最終回の一括精算まで追跡する
- 条件はURLのクエリ（`?p=3300&y=35&r=1.25&s=0.25&rv=5&max=10&cap=0`）に反映されるため、そのまま共有できる

計算ロジックは `src/mortgage/calc.ts`（元利均等返済・見直しごとの返済額再計算＝いわゆる「5年ルール」に近い方式）。
上昇幅やタイミングは想定の一例であり、実際の適用金利・ルール・諸費用は金融機関によって異なる。

### FAX送付状 かんたん作成

送るFAXの種類にチェックを入れると件名と文章が自動で入り、宛名を入れて印刷するだけでA4のFAX送付状ができる単体アプリ（`src/fax/`）。

- 種類: 照会用紙／単位数・TAISコード／計画書・定期モニタリング報告書／計画書のみ／モニタリングのみ／福祉用具貸与実績報告書／御見積書の送付／メーカーへ見積依頼／その他。文面は「FAX送付状テンプレート（5種）」のWord文書をもとにしている（`src/fax/templates.ts`）
- 入力欄は「居宅名・ケアマネ名（横並び）」「ご利用者名・枚数」だけ。文章中の「〇〇」に、ご利用者名（御見積書の送付なら製品名、メーカーへの見積依頼なら商品名）が自動で入る（例:「山田　花子様の計画書及び定期モニタリング報告書を送付いたします。」）
- 送るFAXのチェックは、選んでいる項目をもう一度押すと外れる
- 件名・文章はその場で書き換えられる。「この文面を次回も使う」で種類ごとの標準文面として保存できる
- 印刷デザインは「従来の送信票」（これまでのWordの FAX送信票 を再現）・「表形式の送付状」・「文書形式」から選べる。文書形式は「FAX送付のご案内」という一般的なビジネス文書の形で、日付（右上）・宛先（左）・差出人（右）・表題・拝啓〜敬具・記（数量などと送付枚数）〜以上の順に並べる。入力欄はどのデザインでも同じ
- 印刷の書体は元のWord文書と同じ使い分けにしている。従来の送信票は、見出し・宛名・社名・住所が HG丸ｺﾞｼｯｸM-PRO、日付・枠の中の文章がＭＳ 明朝（英数字は Century）、表形式は游ゴシック、文書形式は明朝（本文12pt）。部品の位置（mm）も元の文書から測った値に合わせてある（`src/fax/fax.css`）。ただし元の文書にあった「平素は格別のご高配を賜り…」の行と2つ目の「敬具」は、言葉が重なるので外し、差出人の部分は重なりのないよう整えている
- これらの書体が入っていないパソコンでは、形の近い Kosugi Maru（丸ゴシックの代わり）・BIZ UD明朝（明朝の代わり）で表示する（`@fontsource` で同梱。使った文字の分だけ読み込まれる）
- 画面右上の「印刷の書体」で、元の書体（Wordと同じ）のほかに HG丸ゴシックM-PRO・ＭＳ 明朝・ＭＳ ゴシック・メイリオ・游ゴシック・游明朝・BIZ UDゴシック・BIZ UD明朝・UDデジタル教科書体 を選べる。選ぶと用紙全体をその書体にそろえる（`src/fax/fonts.ts`。選択はこのブラウザに保存）
- 印刷した宛先（居宅名・ケアマネ名）は保存され、次回からは居宅名の欄に文字を入れると候補に出る。選ぶとケアマネ名まで入る。保存した宛先の削除は画面下の設定で行う
- 差出人（会社名・営業所・担当者・住所・TEL/FAX）は画面下の設定で変更できる
- 画面は13インチのノートパソコン（フルHDを150%表示。ブラウザで使える広さは横1280×縦600前後）を基準にしていて、①種類・②宛名など・③文章・印刷イメージ・印刷ボタンがスクロールなしで1画面に収まる。印刷イメージは画面の高さに合わせて大きさが変わる（`src/fax/fax.css` の `.fx-preview-size`）。縦に余裕のある画面（縦650px・720px・860px以上）では、入力欄・項目名・文章欄・チェック欄も段階的に大きくなる（同じく `--fx-field-h` などの変数）

宛先帳・保存した文面・差出人の設定・印刷デザインは、このブラウザの `localStorage`（`fax-app:` で始まるキー）にだけ保存する。
ご利用者様名などの記入内容は保存しない（画面を閉じると消える）。

#### FAX送付状アプリの公開（GitHub Pages）

公開中のアプリ: https://akamar08taiyo-bot.github.io/-/fax.html （サイトの直下 https://akamar08taiyo-bot.github.io/-/ でも同じアプリが開く）

- GitHub Pages は `gh-pages` ブランチを公開している。中身はFAXアプリのビルド結果だけ
- `claude/fax-cover-sheet-app` ブランチに push すると、`.github/workflows/deploy-fax.yml` が `npm run build:fax` でビルドして `gh-pages` ブランチを丸ごと置き換え、公開中のページが新しいファイルに切り替わったかまで確かめる
- `npm run build:fax` は `dist-fax/` に `index.html` として出力する。読み込むファイルは相対パスなので、`/-/` のような下の階層に置いても、Netlify などのサイト直下に置いても動く（`vite.fax.config.ts`）

## 技術スタック

- フロントエンド: React 19 + TypeScript + Vite（マルチページ）+ Tailwind CSS 4（GitHub Pagesでホスティング）
- グラフ: Recharts
- データ保存: **この端末のブラウザのlocalStorageにのみ保存**（サーバー・アカウント不要）
- ホスティング: GitHub Pages（静的サイトとしてビルドして配信）

サーバー・データベース・APIキーは一切使用しない。アカウント登録やログインも不要で、開いた瞬間から使える。

## セットアップ

**前提:** Node.js 20+

1. 依存関係をインストール
   ```
   npm install
   ```
2. 開発サーバーを起動
   ```
   npm run dev
   ```

環境変数の設定は不要（Firebase等の外部サービスを使わないため）。

## データの保存場所と制約

- すべてのデータ（体重・食事・サプリ・健診記録など）は、開いているブラウザの `localStorage` に保存される
- **別の端末・別のブラウザ・シークレットウィンドウでは、記録したデータは見えない**（この端末のこのブラウザだけのデータ）
- ブラウザの「閲覧データを削除」操作や、ブラウザの再インストールでデータは消える
- 設定画面の「データをエクスポート」でJSON/CSVとしてバックアップ可能。週1回程度のエクスポートを推奨

複数端末での同期や、AIによる食事テキストの自動解析（栄養素の自動入力）を使いたい場合は、Firebase等のバックエンドを別途用意する構成に戻すことも可能（過去のコミット参照）。

## 自動デプロイ（GitHub Actions）

`main` ブランチへのpush時に `.github/workflows/deploy.yml` がビルドしてGitHub Pagesに公開する。

初回のみ、以下を手動でセットアップする。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更

これだけで、以降は `main` へのpush、または GitHub の Actions タブから `workflow_dispatch` で手動実行するとデプロイされる。
公開URLは `https://<GitHubユーザー名>.github.io/<リポジトリ名>/`。

## 実装範囲（MVP）

含む: 体重・体組成記録+推移グラフ、食事記録（テキスト入力→項目分割→手動確認）、よく食べるメニュー、間食管理、筋トレ記録、サプリ管理+重複警告、健診データ入力+前年比、ホームサマリ+改善提案（最大3件）、JSON/CSVエクスポート。

見送り（次フェーズ）: 食事内容のAI自動解析（栄養素の自動推定）、AIアシスタント自由対話、献立提案の高度化、週次レポート自動生成、健診前モード、音声/写真入力、目標体重に基づく自動ペース計算、複数端末間の同期。

## 医療安全上の注意

本アプリは診断を行わず、体重・数値の増減について断定的な評価（「肥満です」等）はしない。
症状トリガー（胸痛・息切れ・動悸・失神・浮腫）が入力された場合は必ず受診相談を促す。
薬・サプリの中止を指示することはなく、医師の指示を常に優先する。
