# 健康管理アプリ（パーソナル食事・健康・筋トレ・サプリ管理）

本人専用の健康管理アプリ。医療診断は行わず、事実の整理・提案・必要時の受診促しに徹する。
体重・体組成の記録を中核機能とし、食事・間食・飲酒・筋トレ・サプリ・健診データを一元管理する。

詳細な要件・画面設計・データ構造・AI判定ルール・医療安全ルールは元の引継ぎ資料を参照。

## 同梱アプリ

このリポジトリは Vite のマルチページ構成で、2つのフロントエンドをビルドする。

| ページ | 内容 |
| --- | --- |
| `index.html` | 健康管理アプリ（食事・健診・筋トレ・サプリ・体重） |
| `mortgage.html` | 住宅ローン 金利シナリオ・シミュレーター |
| `tokutei.html` | 特定福祉用具 購入申請書・見積もり作成（別にビルドする。下の節） |

開発サーバー起動後は `http://localhost:3000/`（健康管理）と `http://localhost:3000/mortgage.html`（シミュレーター）でそれぞれ開ける。
公開後は `https://<ユーザー名>.github.io/<リポジトリ名>/mortgage.html`。

### 住宅ローン 金利シナリオ・シミュレーター

変動金利が段階的に上昇した場合に、月々返済額・残高・総返済額がどう変わるかを試算し、
**金利と総返済額の相関**をグラフで確認するための単体アプリ（Firebase 非依存・入力値はサーバーに送らない）。

- 借入額・返済期間・当初金利・見直し間隔・上昇幅・上限金利をその場で変更して再計算
- 「金利と総返済額の相関」グラフは、X軸を「見直しごとの上昇幅」と「全期間固定金利」で切り替え可能
- 累計利息 / 残高の推移、月々返済額の階段状の推移、区間ごとの内訳表
- 125%ルール（返済額の上昇を直前の1.25倍までに抑える）を有効にすると、未払利息と最終回の一括精算まで追跡する
- 条件はURLのクエリ（`?p=3300&y=35&r=1.25&s=0.25&rv=5&max=10&cap=0`）に反映されるため、そのまま共有できる

計算ロジックは `src/mortgage/calc.ts`（元利均等返済・見直しごとの返済額再計算＝いわゆる「5年ルール」に近い方式）。
上昇幅やタイミングは想定の一例であり、実際の適用金利・ルール・諸費用は金融機関によって異なる。

### 特定福祉用具 購入申請書・見積もり作成（太陽シルバーサービス 行橋営業所）

介護保険の特定福祉用具（入浴補助用具・腰掛便座・多点杖など）の販売で、仕切り一覧表から商品マスタを作り、
★お気に入りから選ぶだけで、定価の2割引きの見積書（介護保険の内訳つき）を作る業務アプリ。ほかのアプリとは独立している。

- 設計と、販売受注簿・見積書・住宅改修アプリなど既存アプリの読み取りメモ：`docs/tokutei/DESIGN.md`・`docs/tokutei/EXISTING_APPS.md`
- コード：`src/tokutei/`（計算は `calc.ts`、種目の判定は `category.ts`、仕切り一覧表の読み取りは `import/`、
  申請書（行橋市・苅田町・みやこ町・広域連合の Excel の原本 `shinsei/` に書き込む）は `shinsei.ts`・`xlsxEdit.ts`）
- 保存：この端末の IndexedDB（`taiyo-tokutei`）だけ。設定からバックアップ（JSON）・商品マスタの CSV 書き出し
- 見積書（販売見積書）は会社の見積書の Excel の原本（`src/tokutei/print/mitsumori.xltx`。所長の印影の画像だけ消したもの）に書き込む（`src/tokutei/estimateBook.ts`）。
  見積もりの画面は左で入れながら、右で原本の形のまま見られる（プレビューの欄を押すと左の入れる所へ）。明細は3ページまで（1ページ目の原本の16行＋明細のつづき42行×2＝100点。ユーザーの指示「ページは3ページまでいけるようにする」「見積もりの行数は4行ぐらい減らしていい」2026-10-25）・備考は3行まで（備考に足す文だけ）。
  原本は薄い水色の地・会社の欄は所長印・担当印の枠の上（I〜K）に左寄せで1行ずつ（会社名 14pt・営業所と所長 12pt・〒・住所・TEL・FAX・登録番号・担当 11pt。2026-10-26）・税率の右に「備考」（算出根拠。「定価28,000円の20%引き」と自動で入り、手で直せる）
  印の枠の上に小さな横長の枠で「所長印」「担当印」（2026-10-26。`docs/tokutei/edit-mitsumori-stamp-labels.py`）。宛名は頭に全角1字あける
  （2026-10-25。原本の直しは `docs/tokutei/edit-mitsumori-template.py`）。入れる所は申請書の画面と同じ形（`components/EstimateInputs.tsx`）。見積日は「2026年10月25日」の形、備考は 10pt。
  メーカー名は打ち込めて、候補（はじめにパナソニックエイジフリー（株）・アロン化成（株）、そのあと商品マスタ・見積もりで使ったメーカー）からも選べる。仕切は任意。
  見積書のプレビューで入れている所は緑の枠（見積書の水色と分かれるよう、住宅改修の見積書と同じ色。2026-10-26）。
  明細の最後の商品の2行下から介護保険の内訳を1行ずつ「介護保険（受領委任払い）」「介護保険の対象　○円」「利用者負担（1割）　○円」（赤字）「保険者負担（9割）　○円」
  （償還払いは「いったんお支払いいただく金額」と払い戻しの行も。ユーザーの指示「備考欄に記載している部分を上にずらす」「この部分のみ記載する形で良い　利用者負担額の部分のみ赤字で記載する」2026-10-26）。
  「自己負担額を表示」（初めからオン）を外すと書かない
  合計・税率ごとの内訳・消費税は原本の式のまま（答えも入れておく）。印刷（PDF）は A4縦1枚、Excel は「〇〇 〇〇様 販売見積書.xlsx」
  （印刷は地の色もプレビューのとおり＝print-color-adjust: exact。ユーザーの指示「印刷するとき、カラーになっていない」2026-10-26）
- 申請書は行橋市・苅田町・みやこ町・広域連合（築上町・豊前市・上毛町・吉富町）の原本に書き込む。広域連合は支給申請書だけの様式で、
  支払方法で受領委任払用（委任状つき）か償還払い用に書き、写真貼付用紙にも書く（2026-10-23。欄は DESIGN.md 5.2）
- 申請書の画面：案件の画面の「📄 申請書」（またはタブ「📄 申請書（行橋市）」など）で、左で入れながら右で申請書の原本の形のまま見る（住宅改修の申請書と同じ。
  ユーザーの指示「特定福祉用具購入の申請書も、住宅改修の申請書と同じくプレビューを見ながら入力することができる」2026-10-22）。
  プレビューの欄を押すと左のその入れる所へ、入れている所の欄は囲む、まだ入っていない所は薄い黄色（`shinseiPreview.ts`・`components/ShinseiPreview.tsx`）
  福祉用具は 種目 → 商品名 → メーカー → 定価・割引率・販売金額（定価×(100−割引率)%。打ち直せて ↺ で戻す。2026-10-26）。2つ目からは下の点線の枠「＋ 2つ目の福祉用具を追加」。
  申請書には数量（「（2台）」）も、理由の頭の種目の名前（「固定用スロープ：」）も書かない（2026-10-26）。
  「🖨 印刷」は初めは1枚目だけ印刷する（上の「1枚目・2枚目…」のチェックで足せる。ユーザーの指示「申請書印刷の場合は、１枚目のみ印刷、デフォルトは」2026-10-26）
- 「📷 スクショから自動認識」（見積もりの画面・申請書の画面の商品の欄。ユーザーの指示「スクショから切り取って作成にすると、自動認識を使えるようにする。
  ケアマックスとウェルファンのカタログにも飛べるように、リンクも準備」2026-10-25）：窓の中に販売受注簿作成ツールの読み取り（`/taiyo-hacchu-scan/?embed=scan`。画像の欄だけ）を出し、
  カタログの商品の画面を切り取って貼り付けると、商品名・メーカー・型番・定価・仕切りが右の欄に入る。直して「見積書に入れる」。窓の上に「🔗 ケアマックス（介援隊）のカタログを開く」

- 販売受注簿への転記：見積もりの画面の「📤 販売受注簿に転記」で、販売受注簿作成ツール（taiyo-hacchu-scan）を新しいタブで開き、商品1点ずつ受注区分「給付」のページにする

## 技術スタック

- フロントエンド: React 19 + TypeScript + Vite（マルチページ）+ Tailwind CSS 4（GitHub Pagesでホスティング）
- グラフ: Recharts
- データ保存: **この端末のブラウザのlocalStorageにのみ保存**（サーバー・アカウント不要）
- ホスティング: GitHub Pages（静的サイトとしてビルドして配信）

サーバー・データベース・APIキーは一切使用しない。アカウント登録やログインも不要で、開いた瞬間から使える。

## セットアップ

**前提:** Node.js 20+

1. 依存関係をインストール
   ```
   npm install
   ```
2. 開発サーバーを起動
   ```
   npm run dev
   ```

環境変数の設定は不要（Firebase等の外部サービスを使わないため）。

## データの保存場所と制約

- すべてのデータ（体重・食事・サプリ・健診記録など）は、開いているブラウザの `localStorage` に保存される
- **別の端末・別のブラウザ・シークレットウィンドウでは、記録したデータは見えない**（この端末のこのブラウザだけのデータ）
- ブラウザの「閲覧データを削除」操作や、ブラウザの再インストールでデータは消える
- 設定画面の「データをエクスポート」でJSON/CSVとしてバックアップ可能。週1回程度のエクスポートを推奨

複数端末での同期や、AIによる食事テキストの自動解析（栄養素の自動入力）を使いたい場合は、Firebase等のバックエンドを別途用意する構成に戻すことも可能（過去のコミット参照）。

## 自動デプロイ（GitHub Actions）

`main` ブランチへのpush時に `.github/workflows/deploy.yml` がビルドしてGitHub Pagesに公開する。

初回のみ、以下を手動でセットアップする。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更

これだけで、以降は `main` へのpush、または GitHub の Actions タブから `workflow_dispatch` で手動実行するとデプロイされる。
公開URLは `https://<GitHubユーザー名>.github.io/<リポジトリ名>/`。

## 実装範囲（MVP）

含む: 体重・体組成記録+推移グラフ、食事記録（テキスト入力→項目分割→手動確認）、よく食べるメニュー、間食管理、筋トレ記録、サプリ管理+重複警告、健診データ入力+前年比、ホームサマリ+改善提案（最大3件）、JSON/CSVエクスポート。

見送り（次フェーズ）: 食事内容のAI自動解析（栄養素の自動推定）、AIアシスタント自由対話、献立提案の高度化、週次レポート自動生成、健診前モード、音声/写真入力、目標体重に基づく自動ペース計算、複数端末間の同期。

## 医療安全上の注意

本アプリは診断を行わず、体重・数値の増減について断定的な評価（「肥満です」等）はしない。
症状トリガー（胸痛・息切れ・動悸・失神・浮腫）が入力された場合は必ず受診相談を促す。
薬・サプリの中止を指示することはなく、医師の指示を常に優先する。
