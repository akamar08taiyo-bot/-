# 健康管理アプリ（パーソナル食事・健康・筋トレ・サプリ管理）

本人専用の健康管理アプリ。医療診断は行わず、事実の整理・提案・必要時の受診促しに徹する。
体重・体組成の記録を中核機能とし、食事・間食・飲酒・筋トレ・サプリ・健診データを一元管理する。

詳細な要件・画面設計・データ構造・AI判定ルール・医療安全ルールは元の引継ぎ資料を参照。

## 同梱アプリ

このリポジトリは Vite のマルチページ構成で、4つのフロントエンドをビルドする。

| ページ | 内容 |
| --- | --- |
| `index.html` | 健康管理アプリ（食事・健診・筋トレ・サプリ・体重） |
| `mortgage.html` | 住宅ローン 金利シナリオ・シミュレーター |
| `sasaoka.html` | 仕切り計算・請求書作成（笹岡工務店）※1ファイルにビルドして太陽ポータルに置く |
| `jutaku.html` | 住宅改修 見積書作成 ※1ファイルにビルドして太陽ポータルに置く（仕切り計算・請求書作成とデータを一緒に使う） |

開発サーバー起動後は `http://localhost:3000/`（健康管理）と `http://localhost:3000/mortgage.html`（シミュレーター）でそれぞれ開ける。
公開後は `https://<ユーザー名>.github.io/<リポジトリ名>/mortgage.html`。

### 住宅ローン 金利シナリオ・シミュレーター

変動金利が段階的に上昇した場合に、月々返済額・残高・総返済額がどう変わるかを試算し、
**金利と総返済額の相関**をグラフで確認するための単体アプリ（Firebase 非依存・入力値はサーバーに送らない）。

- 借入額・返済期間・当初金利・見直し間隔・上昇幅・上限金利をその場で変更して再計算
- 「金利と総返済額の相関」グラフは、X軸を「見直しごとの上昇幅」と「全期間固定金利」で切り替え可能
- 累計利息 / 残高の推移、月々返済額の階段状の推移、区間ごとの内訳表
- 125%ルール（返済額の上昇を直前の1.25倍までに抑える）を有効にすると、未払利息と最終回の一括精算まで追跡する
- 条件はURLのクエリ（`?p=3300&y=35&r=1.25&s=0.25&rv=5&max=10&cap=0`）に反映されるため、そのまま共有できる

計算ロジックは `src/mortgage/calc.ts`（元利均等返済・見直しごとの返済額再計算＝いわゆる「5年ルール」に近い方式）。
上昇幅やタイミングは想定の一例であり、実際の適用金利・ルール・諸費用は金融機関によって異なる。

### 住宅改修 見積書・請求書（笹岡工務店）

1つのアプリ（`src/sasaoka/App.tsx`）を4つのタブで切り替えて使う。太陽ポータルの2つの入口（`jutaku-mitsumori/`＝`jutaku.html`、`sasaoka/`＝`sasaoka.html`）に
同じアプリを置き、最初に開くタブだけを変える（同じサイトなので、部材リスト・★お気に入り・部材＋施工費（常用）・設定・様邸（見積書）は同じ保存場所）。

- **📝 見積もりを作成する**（`estimate/`）：最初に「＋ 新規作成」で保険者（苅田町・行橋市・みやこ町・広域連合）を選ぶか（苅田町・行橋市・みやこ町は同じ書式「工事費見積書兼工事費内訳書」、
  広域連合は「住宅改修内訳明細書」。申請書は保険者ごとに違うので、見積書ごとに保険者を持つ）、
  「📋 一覧から作成」（作成日の月ごとの一覧。◀ ▶ で月を変える。探すときはすべての月から。行ごとに 印刷・Excel・複製・削除）を選ぶ。
  見積書は、いただいた Excel の形のまま、Excel と同じように欄を選んで打ち込んで作り、A4横で印刷する。Excel ファイル（.xlsx）でも保存できる。
  見積書に入れた部材（仕切価格）と施工費は、そのまま笹岡工務店の仕切り計算表と請求書（請求する月の分）に入り、自動で計算される
  （新しい見積書・複製は最初から「笹岡工務店の請求書に入れる」。笹岡工務店の工事でない見積書は外す）。
- **🧾 請求書を確認する**：請求する月ごとの様邸（仕切り計算表）と1か月分の「御請求書」を作り、A4で印刷する。
  もとは Excel の「笹岡工務店仕切り計算表」と、スキャンした「笹岡手間」（取付手間の単価表）。見積書と様邸は同じデータなので、どちらで直しても両方に入る。
- **📦 部材・施工費マスタ**：部材リスト（メーカーの仕切価格・定価）と、施工費（笹岡工務店の取付手間の単価）と、部材＋施工費（常用）のセット。
- **⚙ 設定**：見積書と請求書の両方の設定。

- **部材リスト（メーカー仕切り）**：メーカーの仕切り表を Excel（.xlsx）・CSV（Shift_JIS / UTF-8）・PDF・貼り付けた表から読み取る（`priceImport.ts`・`xlsx.ts`・`pdfText.ts`）。
  見出し（商品名・品番・仕切価格・定価・メーカー）を探して列を自動で選び、「定価」と「仕切」があれば仕切を使う。見出しのない表・PDFは「1行ずつ読む」（行の右から何番目の金額を仕切価格にするか選ぶ）。
  取り込む行・★（お気に入り）を選んでから入れる。同じメーカーで品番（なければ商品名）が同じものは価格だけ書き換え、★は残す。
  部材を選ぶ画面の「★ お気に入り」では、行の「削除」でお気に入りから外す（部材リストには残り、「すべて」で★を押すとまた入る）。
  「定価」の列（定価・希望小売・標準価格・上代・ガイド価格）も読み、見積書の単価に使う（定価の見出しの列は仕切価格にしない）（見出しのない表は、仕切価格の左の列がほとんど仕切価格以上なら定価とみなす。「1行ずつ読む」は右から何番目を定価にするか選べる）。
  改定前・改定後の「定価」「売価」が並ぶ表（TOTO）は右の新しい方。「掛率」「UP率」など「率」の列は価格にしない。「1本の長さ」の列（m・mm・cm）があれば読む。
  見出しが2行の表（マツ六の価格改定一覧：「現行価格」「価格改定価格」の下に「定価・単価・掛率」）は下の行の言葉で列を決め、右の組（改定後）の単価を仕切価格、定価を定価にする。
  「商品名2」の先頭に品番（BD-01BK など）があれば品番にし、色・寸法は商品名のうしろへ（品番の列が「商品コード」「JANコード」のとき。「品番」「型番」の列ならそのまま）。
  「掛率」の列があれば、仕切価格の欄が空の行は 定価×掛率（表の率。1円未満は四捨五入。決まった率では計算しない）。
  仕切価格は空欄でも定価があれば取り込み（あとで仕切価格の入った同じ形の表、または品番と仕切価格だけの表を取り込むと仕切価格だけが入る）。
  **仕切価格が空欄の部材は、定価からは計算しない**（ユーザーの指示「仕切り価格は0.8ではありません」。仕切りの率はメーカーごとに違う。`calc.ts` の `shikiriPrice`）。
  部材を選ぶ画面では「空欄」と出し、見積書の画面で「仕切価格が空欄の部材が N 行あります」と知らせて、その場で入れられる（請求書では入れるまで0円）。
  **定価が空欄の部材は 仕切価格×1.25（1円未満切り上げ。見積の単価 定価×0.8 で仕切価格と同じ金額）**（`listPriceOf`。入れた値があればそちら）。
  メーカーの仕切り表を入れ直すときは、部材リストの「仕切価格が空欄の○件を消す」「🗑 部材リストを空にする」（施工費・部材＋施工費（常用）・作った見積書は消えない）。
  定価より右の見出しのない列に金額があれば仕切価格とみなす（マツ六の価格表は仕切価格の列の見出しが空）。
  「品番等」に品番と寸法・色が一緒に入っている表（マツ六「BD-134 φ35×4000mm Mオーク」）は品番と分け、寸法・色は商品名のうしろへ。「HD5-4000 T LBR」（矢崎化工）のように英数字だけ続くものは品番のまま。
  同じ品番で寸法・色の違う商品（「P-30V I-40」「P-30V I-60」など）は商品名で分けて別々に残す。
  入数・単位の「1個」「1本」は「個」「本」に（「10枚」のような2つ以上入りはそのまま）。商品名のうしろにくり返された品番は外す。
  手すりのパイプ・丸棒・木製の取付けベースで、商品名に長さがなく品番に「-2000」「-4000」とあるもの（矢崎化工「HCT-4000 T USL」）は、それを1本の長さ（mm）にする。
  PDFの表は、見出しの行の語の位置で列を分ける。見出しと重ならない語は、その列のほかの行の語が並ぶ範囲で決める
  （矢崎化工の改定価格表は見出しが列のまん中にあり、商品名が見出しより左から始まる。改定後のガイド価格を定価にし、上下の行に見出しが分かれた「価格改定」の〇×は見出しのない列にする）
- PDFは文字の入ったものだけ（コピー機でスキャンした画像だけのPDFは読めない。OCR も試したが、表の数字を取り込めるほど正しく読めなかった。スキャンした価格表は文字に起こした Excel にして取り込む）。pdf.js は最新ブラウザにしかない機能を使うため legacy 版を使い、日本語のCMap（`Adobe-Japan1-UCS2` など）を同梱して、フォントを埋め込んでいない日本語PDFも読めるようにしている
- **取付手間の単価（施工費）**：「笹岡手間」の17項目。1箇所あたりの **仕切り（笹岡工務店からの請求）と見積（見積書に入れる単価）の両方** を持つ（`LaborItem.price`・`estPrice`。
  最初の値は 木 仕切り1,000円・見積1,500円、タイル 1,500円・2,000円 など。見積はユーザーにいただいた表の右の列。表になかった「踏台 木」は見積2,000円（「踏み台は取り付け1箇所2000円で計算」の指示）。
  見積が空欄の項目は 仕切り×1.5（設定の率）。前の版で保存したマスタ・見積書の「踏台 木」の空欄は、読み込んだときに一度だけ 2,000円にする（設定の `laborRev`。手で入れた単価は変えない））。
  部材・施工費マスタの「施工費（笹岡工務店の手間）」で両方を直せる。前の版で作った見積書の施工費の行にも、読み込んだときに一度だけ見積の単価を入れる（設定の `laborEst`）。
  様邸の画面（見積書では「🔧 施工費（笹岡工務店の手間）から入れる」。部材を選んでいればその部材の同上施工費）で ＋／− を押して箇所数を数える（「1箇所 仕切り 1,000円・見積 1,500円」）。
  部材を選ぶ画面でも、入れた部材は ＋／− で数量を変えられる（0 にすると行を消す）
- **様邸**：○○様邸（お客様名の横で担当を選ぶ。候補は設定の「担当者の候補」で、最初は 久保 匠史・土居 翔太・宮村 茉莉花・信田 裕太・藤田 知美。見積書にはフルネーム、請求書・一覧には名字だけを出す）→ 箇所（玄関・トイレなど）→ 行（部材 または 取付手間）。行は ＋ でいくつでも足せる。行には選んだときの品名・単価を書き写すので、あとで部材リストや単価を変えても作った様邸の金額は変わらない。
  部材・工事は品名なしで金額だけの行も入れられる（「＋ 部材を金額だけ入れる」「＋ 工事を金額だけ入れる」）。品名・単価・数量は行の上で手で直せる
- **部材＋施工費（常用）**（`rows.ts`・`components/Kits.tsx`・`components/KitsPage.tsx`。データでは kits）：部材・施工費マスタの「部材＋施工費（常用）」のタブで、セット（名前・部材・施工費）を登録・直す（📋 部材リストから入れる／部材の行の「🔧 施工費」でその部材の同上施工費を数える／🔧 施工費を入れる／数量の ＋−・並べ替え・行の削除・セットの複製・削除）。見積書・様邸の選ぶ画面の「📦 部材・施工費マスタで登録・直す」からも開ける。
  箇所の部材・取付手間の組み合わせを「この箇所を部材＋施工費（常用）に登録」で名前を付けて残すこともでき、「＋ 部材＋施工費（常用）から入れる」で別の箇所・様邸にまとめて入れる。入れるときは部材リスト・手間単価の今の単価・定価にする。
  最初に例のセット「（例）手すり BD-134＋金具 BD-08G＋施工費」を1つ入れる（`samples.ts` の `exampleKit`。BD-134・BD-08G は数量を空けておき、施工費は木 2箇所＝見積 3,000円。
  部材リストに同じ品番があればその部材の単価・定価。1回だけ入れる＝設定の `kitExample`。消してもまた入らない）。数量が 0 の部材の行は、見積書・印刷・Excel で数量・金額を空欄にする（あとで本数を書く行）
- **計算**（`calc.ts`）：元の仕切り計算表と同じ ① 部材代 ② 取付手間 ③ 部材上乗せ＝①×0.07 ④ 諸経費＝（①＋②＋③）×0.07 ⑦ 税抜＝①〜④ ⑤ 消費税＝⑦×0.1－1（元の表の式。設定で切り捨て等に変更可）⑥ 合計＝⑦＋⑤。
  ③④⑤は1円単位にしてから足す（Excelは小数のまま持って表示だけ丸めるので、⑥が1円ずれることがあった）。
  切って使う部材（見積書で長さを入れた手すりなど）は、見積書と同じ本数で数える（仕切価格10,000円・1本4m を60cm → 600mm÷4000mm＝0.15本・1,500円。1円未満は四捨五入）
- **御請求書（1か月分）**：様邸ごとに 担当・部材代・取付手間・部材上乗せ・諸経費・税抜計 を並べ、すべての様邸の税抜合計に最後に消費税率をかける（1円未満は切り捨て。設定で四捨五入・切り上げ、様邸ごとの⑤消費税を足す形にも変えられる）。
  前の版で保存した設定（様邸ごとに足す形）は、読み込むときに「合計にかける」形に直す（設定の `rev`）。発行元は営業所を選ぶと住所・電話・所長名が入り、「○○営業所所長　氏名」と出る（太陽ポータルで選んだ営業所を最初から使う。所長名は見積・提案書作成アプリの営業所一覧と同じ）
- **見積書**（`calc.ts` の estimate〜・`estimateForms.ts`・`print/EstimateForms.tsx`）：部材の単価は 定価×0.8（設定で変えられる）。規格品をそのまま使うときは数量＝本数。
  手すりなどを切って使うときは、数量に 0.15 や 60cm と入れると 数量＝使う長さ÷1本の長さ（m）。例：定価20,000円（1本4m）を60cm → 0.15本・単価16,000円・金額2,400円。
  1本の長さは部材ごとに持ち、商品名の「4m」「2000mm」「L=4000」などから自動で入る（部材リストで直せる）。
  部材のすぐ下に続く取付手間の行は、見積書では「同上施工費」1行にまとめる（「＋ この部材の施工費（取付手間を数える）」で数える。金額は見積の単価×箇所数。例：木 2箇所＝3,000円）。
  見積書は、いただいた Excel の書式どおり A4横に印刷する（役所の様式なので枠の大きさは変えない）。
  **保険者**（様邸の `insurer`：kanda 苅田町／yukuhashi 行橋市／miyako みやこ町／kouiki 広域連合＝築上町・豊前市・上毛町・吉富町。`estimateForms.ts` の `INSURER_INFO`）を
  見積書を作るときに選び（「＋ 苅田町」「＋ 行橋市」「＋ みやこ町」「＋ 広域連合」）、見積書の画面の「保険者」で選び直せる。書式は保険者で決まる（`jobForm`）。
  「📝 申請書を作成」（下の 申請書）は、保険者の申請書の原本に転記する。
  工事場所の住所の市町村が保険者と違うときは、知らせてボタンで変える（「保険者をみやこ町にする」。打っている途中で勝手に変えない）。
  保険者を選ぶ前に保存した見積書は、住所の市町村（書式と食い違わないとき）か、広域連合用の書式なら広域連合。分からなければ空（見積書の画面で選ぶ。書式は前のまま）。
  請求書を確認するで作った様邸（保険者・書式を選んでいないもの）は、住所の市町村、分からなければ設定の書式。
  金額は元の Excel と同じく ROUNDDOWN（単価＝定価×0.8、金額＝数量×単価、諸経費＝小計×0.1、消費税＝（小計＋諸経費）×0.1。どれも1円未満を切り捨て）。最後のページの下4行が 小計・諸経費・消費税・合計（全体と介護保険の対象の両方）。
  見積書の諸経費は端数の調整などで見積書ごとに手で直せる（消すと小計×0.1に戻る）。仕切り計算表の④諸経費は一律の式のまま。
  備考（定価等）・算出根拠は「定価8,000円（税抜）×0.8」（見積の単価を手で入れた行は ×0.8 を付けない）。切って使う部材は数量を「本」で書き、備考は「定価20,000円（4m）×0.8」（かっこは1本の長さ）、2行目に mm で「600mm÷4000mm＝0.15」のように長さの計算を書く。

  同じ部材（メーカー・品番・品名が同じ）は箇所をまたいで足す。施工費・空白の行・金額だけの行は入れない。規格品をそのまま使う部材は見積書の数量のまま。


公開中：太陽ポータル（taiyo-portal リポジトリ）の `sasaoka/index.html`（タイル名「仕切り計算・請求書作成」）と `jutaku-mitsumori/index.html`（タイル名「住宅改修 見積書作成」）。
直したときは、このブランチでビルド → `dist-sasaoka/` の `index.html` と `version.json` を taiyo-portal の `sasaoka/` に、`dist-jutaku/` の2つを `jutaku-mitsumori/` に上書き → taiyo-portal の master に push（GitHub Pages が自動で公開する）。
`version.json` はビルドした日時（`vite.version.ts`。アプリにも同じ印を埋め込む）。スマホのブラウザは前に開いたページをしばらく覚えていて直した版がすぐ出ないことがあるので、アプリは開いて少ししてからと画面に戻ったときに `version.json` を見て、印が違えば上に「このアプリの新しい版が出ています ⟳ 読み込み直す」を出す（`update.ts`。保存してから読み込み直す）。
2つは必ず同じサイトに置く（別のサイトだとデータ（IndexedDB）が別になり、部材リストも請求書も連動しない）。ポータルと同じサイトなので、ポータルで選んだ営業所（`localStorage` の `taiyo_portal_session`）を発行元・施工業者に使う。
パソコンに保存したファイルで開いたときのデータは、ポータルのデータとは別（移すときはバックアップを使う）。

## 技術スタック

- フロントエンド: React 19 + TypeScript + Vite（マルチページ）+ Tailwind CSS 4（GitHub Pagesでホスティング）
- グラフ: Recharts
- データ保存: **この端末のブラウザのlocalStorageにのみ保存**（サーバー・アカウント不要）
- ホスティング: GitHub Pages（静的サイトとしてビルドして配信）

サーバー・データベース・APIキーは一切使用しない。アカウント登録やログインも不要で、開いた瞬間から使える。

## セットアップ

**前提:** Node.js 20+

1. 依存関係をインストール
   ```
   npm install
   ```
2. 開発サーバーを起動
   ```
   npm run dev
   ```

環境変数の設定は不要（Firebase等の外部サービスを使わないため）。

## データの保存場所と制約

- すべてのデータ（体重・食事・サプリ・健診記録など）は、開いているブラウザの `localStorage` に保存される
- **別の端末・別のブラウザ・シークレットウィンドウでは、記録したデータは見えない**（この端末のこのブラウザだけのデータ）
- ブラウザの「閲覧データを削除」操作や、ブラウザの再インストールでデータは消える
- 設定画面の「データをエクスポート」でJSON/CSVとしてバックアップ可能。週1回程度のエクスポートを推奨

複数端末での同期や、AIによる食事テキストの自動解析（栄養素の自動入力）を使いたい場合は、Firebase等のバックエンドを別途用意する構成に戻すことも可能（過去のコミット参照）。

## 自動デプロイ（GitHub Actions）

`main` ブランチへのpush時に `.github/workflows/deploy.yml` がビルドしてGitHub Pagesに公開する。

初回のみ、以下を手動でセットアップする。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更

これだけで、以降は `main` へのpush、または GitHub の Actions タブから `workflow_dispatch` で手動実行するとデプロイされる。
公開URLは `https://<GitHubユーザー名>.github.io/<リポジトリ名>/`。

## 実装範囲（MVP）

含む: 体重・体組成記録+推移グラフ、食事記録（テキスト入力→項目分割→手動確認）、よく食べるメニュー、間食管理、筋トレ記録、サプリ管理+重複警告、健診データ入力+前年比、ホームサマリ+改善提案（最大3件）、JSON/CSVエクスポート。

見送り（次フェーズ）: 食事内容のAI自動解析（栄養素の自動推定）、AIアシスタント自由対話、献立提案の高度化、週次レポート自動生成、健診前モード、音声/写真入力、目標体重に基づく自動ペース計算、複数端末間の同期。

## 医療安全上の注意

本アプリは診断を行わず、体重・数値の増減について断定的な評価（「肥満です」等）はしない。
症状トリガー（胸痛・息切れ・動悸・失神・浮腫）が入力された場合は必ず受診相談を促す。
薬・サプリの中止を指示することはなく、医師の指示を常に優先する。
