# 健康管理アプリ（パーソナル食事・健康・筋トレ・サプリ管理）

本人専用の健康管理アプリ。医療診断は行わず、事実の整理・提案・必要時の受診促しに徹する。
体重・体組成の記録を中核機能とし、食事・間食・飲酒・筋トレ・サプリ・健診データを一元管理する。

詳細な要件・画面設計・データ構造・AI判定ルール・医療安全ルールは元の引継ぎ資料を参照。

## 同梱アプリ

このリポジトリは Vite のマルチページ構成で、3つのフロントエンドをビルドする。

| ページ | 内容 |
| --- | --- |
| `index.html` | 健康管理アプリ（食事・健診・筋トレ・サプリ・体重） |
| `mortgage.html` | 住宅ローン 金利シナリオ・シミュレーター |
| `sasaoka.html` | 仕切り計算・請求書作成（笹岡工務店）※1ファイルにビルドして太陽ポータルに置く |

開発サーバー起動後は `http://localhost:3000/`（健康管理）と `http://localhost:3000/mortgage.html`（シミュレーター）でそれぞれ開ける。
公開後は `https://<ユーザー名>.github.io/<リポジトリ名>/mortgage.html`。

### 住宅ローン 金利シナリオ・シミュレーター

変動金利が段階的に上昇した場合に、月々返済額・残高・総返済額がどう変わるかを試算し、
**金利と総返済額の相関**をグラフで確認するための単体アプリ（Firebase 非依存・入力値はサーバーに送らない）。

- 借入額・返済期間・当初金利・見直し間隔・上昇幅・上限金利をその場で変更して再計算
- 「金利と総返済額の相関」グラフは、X軸を「見直しごとの上昇幅」と「全期間固定金利」で切り替え可能
- 累計利息 / 残高の推移、月々返済額の階段状の推移、区間ごとの内訳表
- 125%ルール（返済額の上昇を直前の1.25倍までに抑える）を有効にすると、未払利息と最終回の一括精算まで追跡する
- 条件はURLのクエリ（`?p=3300&y=35&r=1.25&s=0.25&rv=5&max=10&cap=0`）に反映されるため、そのまま共有できる

計算ロジックは `src/mortgage/calc.ts`（元利均等返済・見直しごとの返済額再計算＝いわゆる「5年ルール」に近い方式）。
上昇幅やタイミングは想定の一例であり、実際の適用金利・ルール・諸費用は金融機関によって異なる。

### 仕切り計算・請求書作成（笹岡工務店）

メーカーの仕切り表から部材を選び、取付手間の箇所数を数えて、様邸ごとの「仕切り計算表」と1か月分の「御請求書」を作り、A4で印刷する単体アプリ（`src/sasaoka/`）。
同じ入力から介護保険住宅改修の見積書も作れる（画面上の「見積作成」に切り替える。苅田町・行橋用「工事費見積書兼工事費内訳書」と、みやこ町・広域連合用「住宅改修内訳明細書」）。
もとは Excel の「笹岡工務店仕切り計算表」と、スキャンした「笹岡手間」（取付手間の単価表）。

- **部材リスト（メーカー仕切り）**：メーカーの仕切り表を Excel（.xlsx）・CSV（Shift_JIS / UTF-8）・PDF・貼り付けた表から読み取る（`priceImport.ts`・`xlsx.ts`・`pdfText.ts`）。
  見出し（商品名・品番・仕切価格・定価・メーカー）を探して列を自動で選び、「定価」と「仕切」があれば仕切を使う。見出しのない表・PDFは「1行ずつ読む」（行の右から何番目の金額を仕切価格にするか選ぶ）。
  取り込む行・★（お気に入り）を選んでから入れる。同じメーカーで品番（なければ商品名）が同じものは価格だけ書き換え、★は残す。
  「定価」の列（定価・希望小売・標準価格・上代）も読み、見積書の単価に使う（見出しのない表は、仕切価格の左の列がほとんど仕切価格以上なら定価とみなす。「1行ずつ読む」は右から何番目を定価にするか選べる）。
  改定前・改定後の「定価」「売価」が並ぶ表（TOTO）は右の新しい方。「掛率」「UP率」など「率」の列は価格にしない。「1本の長さ」の列（m・mm・cm）があれば読む。
  仕切価格は空欄でも定価があれば取り込み（あとで仕切価格の入った同じ形の表、または品番と仕切価格だけの表を取り込むと仕切価格だけが入る）。
  定価より右の見出しのない列に金額があれば仕切価格とみなす（マツ六の価格表は仕切価格の列の見出しが空）。
  「品番等」に品番と寸法・色が一緒に入っている表（マツ六「BD-134 φ35×4000mm Mオーク」）は品番と分け、寸法・色は商品名のうしろへ。「HD5-4000 T LBR」（矢崎化工）のように英数字だけ続くものは品番のまま。
  同じ品番で寸法・色の違う商品（「P-30V I-40」「P-30V I-60」など）は商品名で分けて別々に残す
- PDFは文字の入ったものだけ（スキャンした画像だけのPDFは読めない）。pdf.js は最新ブラウザにしかない機能を使うため legacy 版を使い、日本語のCMap（`Adobe-Japan1-UCS2` など）を同梱して、フォントを埋め込んでいない日本語PDFも読めるようにしている
- **取付手間の単価**：「笹岡手間」の17項目（木 1,000円／1箇所 など）。様邸の画面で ＋／− を押して箇所数を数える
- **様邸**：○○様邸（お客様名の横で担当を選ぶ。候補は設定の「担当者の候補」で、最初は 久保 匠史・土居 翔太・宮村 茉莉花・信田 裕太・藤田 知美。見積書にはフルネーム、請求書・一覧には名字だけを出す）→ 箇所（玄関・トイレなど）→ 行（部材 または 取付手間）。行は ＋ でいくつでも足せる。行には選んだときの品名・単価を書き写すので、あとで部材リストや単価を変えても作った様邸の金額は変わらない。
  部材・工事は品名なしで金額だけの行も入れられる（「＋ 部材を金額だけ入れる」「＋ 工事を金額だけ入れる」）。品名・単価・数量は行の上で手で直せる
- **一式**（`rows.ts`）：箇所の部材・取付手間の組み合わせを「この箇所を一式に登録」で名前を付けて残し、「＋ 一式から入れる」で別の箇所・様邸にまとめて入れる。入れるときは部材リスト・手間単価の今の単価・定価にする
- **計算**（`calc.ts`）：元の仕切り計算表と同じ ① 部材代 ② 取付手間 ③ 部材上乗せ＝①×0.07 ④ 諸経費＝（①＋②＋③）×0.07 ⑦ 税抜＝①〜④ ⑤ 消費税＝⑦×0.1－1（元の表の式。設定で切り捨て等に変更可）⑥ 合計＝⑦＋⑤。
  ③④⑤は1円単位にしてから足す（Excelは小数のまま持って表示だけ丸めるので、⑥が1円ずれることがあった）
- **御請求書（1か月分）**：様邸ごとに 担当・部材代・取付手間・部材上乗せ・諸経費・税抜計 を並べ、すべての様邸の税抜合計に最後に消費税率をかける（1円未満は切り捨て。設定で四捨五入・切り上げ、様邸ごとの⑤消費税を足す形にも変えられる）。
  前の版で保存した設定（様邸ごとに足す形）は、読み込むときに「合計にかける」形に直す（設定の `rev`）。発行元は営業所を選ぶと住所・電話・所長名が入り、「○○営業所所長　氏名」と出る（太陽ポータルで選んだ営業所を最初から使う。所長名は見積・提案書作成アプリの営業所一覧と同じ）
- **見積作成**（画面上の切り替え。`calc.ts` の estimate〜）：部材の単価は 定価×0.8（設定で変えられる）。規格品をそのまま使うときは数量＝本数。
  手すりなどを切って使うときは「使う長さ（cm）」を入れると、数量＝使う長さ÷1本の長さ（m）。例：定価20,000円（1本4m）を60cm → 0.15本・単価16,000円・金額2,400円。
  1本の長さは部材ごとに持ち、商品名の「4m」「2000mm」「L=4000」などから自動で入る（部材リスト・様邸の行で直せる）。
  見積の単価は手で直せる（↺で自動に戻す）。部材のすぐ下に続く取付手間の行は、見積書では「同上施工費」1行にまとめる（部材ごとの「＋ この部材の施工費」で数える。例：木 2箇所＝2,000円）。
  見積書（`estimateForms.ts`・`print/EstimateForms.tsx`）は、いただいた Excel の書式どおり A4横に印刷する（役所の様式なので枠の大きさは変えない）。様邸の住所の市町村で書式が決まり（みやこ町・築上町・豊前市・上毛町・吉富町 → 住宅改修内訳明細書、行橋市・苅田町 → 工事費見積書兼工事費内訳書、ほかは設定の書式）、様邸ごとに2つのどちらかを選び直せる（住所で決まる方を選んだときは、住所に合わせて変わるまま）。
  金額は元の Excel と同じく ROUNDDOWN（単価＝定価×0.8、金額＝数量×単価、諸経費＝小計×0.1、消費税＝（小計＋諸経費）×0.1。どれも1円未満を切り捨て）。最後のページの下4行が 小計・諸経費・消費税・合計（全体と介護保険の対象の両方）。
  見積書の諸経費は端数の調整などで様邸ごとに手で直せる（↺で小計×0.1に戻す）。仕切り計算表の④諸経費は一律の式のまま。
  切って使う部材は数量を「本」で書き、備考（定価等）・算出根拠に「定価：￥20,000×0.8」「0.6m÷4m＝0.15本」のように計算を書く。
  苅田町・行橋用：1ページ18行。改修内容（改修の種類）・改修場所（箇所名＋写真番号）・内容（メーカー 品番 品名）・数量・単価・金額・介護保険対象部分・対象外金額・備考「定価：￥…」。施工費は「1式」。被保険者番号・施工業者名・代表者（所長）・担当と電話・作成日（令和）
  みやこ町・広域連合用（福岡県介護保険広域連合の様式）：1ページ14行。2ページ以上になっても1つの見積書で、ページの下に Ｐ－1・Ｐ－2 と入る。改修箇所（室名）・工事名称・材／手・部材・仕様・全改修工事部分・写真番号・改修の種類・対象工事部分・算出根拠（定価○円/本、施工費は「1時間2,500円」。施工費は 時間×2,500円 で書き、割り切れない金額は1式）
  箇所ごとに 改修の種類（①〜⑥）・写真番号（空なら順番）・工事名称、行ごとに「介護保険の対象外」（部材のすぐ下の同上施工費は部材に合わせる）を入れる。箇所の行はなるべく同じページに入れる
  見積作成で様邸を開くと、右に見積書（その様邸の書式）を縮めて映す（`components/EstimatePreview.tsx`）。左で入力するとすぐに右に入り、入力している行は両方に色が付く。
  右の見積書の欄をクリックすると、その欄を打ち直せる（Enter で決定・Esc でやめる・Tab で次の欄。↺ で元に戻す）。数量・単価・定価・単位・箇所名・写真番号・改修の種類・住所・お客様名・被保険者番号・介護保険の対象外・諸経費は左の入力と同じ値が変わる。
  内容（品名）・備考（算出根拠）・施工費の名前と金額（みやこ町・広域連合用は時間でも）は見積書だけの値（行の `estText`・`estNote`・`estAmount`）で、仕切り計算表・請求書・部材リストは変わらない（左の行に「見積書の内容」などと出る）。
  作成日は印刷の画面と同じ値。「🔍 拡大」で印刷と同じ大きさ（横に動かして見る）、「隠す」で入力を広く使う（この端末で覚えておく）。画面が狭いときは入力の下に映す
- 印刷：様邸ごとの明細（箇所ごとの表＋①〜⑦）と、請求書＋全様邸の明細のまとめて印刷（A4縦）、見積書（A4横）。印刷の画面で「PDFに保存」を選べばPDFにできる。スマホなど画面が狭いときは、印刷イメージを画面の幅に縮めて見せる（「拡大」で原寸。印刷は常に原寸）
- データはこの端末のブラウザの IndexedDB だけに保存（太陽ポータルのアプリは同じサイトで localStorage の容量を分け合うため、件数の多い部材リストは IndexedDB に入れる）。設定画面からバックアップ（JSON）の保存・読み込み、部材リスト・手間単価だけのファイルの受け渡しができる

#### ビルド・公開

```
npm run build:sasaoka    # dist-sasaoka/index.html に1ファイル（約2.8MB、JS・CSS・PDF読み取り用データを同梱）
```

1ファイルなので、太陽ポータル（taiyo-portal）の中のフォルダ（書類送付状の `soufujo/` と同じ形）に置き、`APPS` に1件足せば組み込める。サイト直下に置いても、パソコンに保存して開いても動く。

公開中：太陽ポータル（taiyo-portal リポジトリの `sasaoka/index.html`、タイル名「仕切り計算・請求書作成」）。
直したときは、このブランチで `npm run build:sasaoka` → `dist-sasaoka/index.html` を taiyo-portal の `sasaoka/index.html` に上書き → taiyo-portal の master に push（GitHub Pages が自動で公開する）。
ポータルと同じサイトで開くので、ポータルで選んだ営業所（`localStorage` の `taiyo_portal_session`）を発行元に使う。データ（IndexedDB の `taiyo-sasaoka-shikiri`）もこのサイトのものになり、パソコンに保存したファイルで試したときのデータとは別になる（移すときはバックアップを使う）。

#### テスト

```
npm run test:sasaoka     # 計算（仕切り・請求書・見積）・行の操作・保存データの読み込み・仕切り表の読み取り（Excel/CSV/PDFの表）の単体テスト
npm run build:sasaoka && npx http-server dist-sasaoka -p 5180 &
node test/sasaoka/e2e.mjs http://127.0.0.1:5180/index.html /tmp/out           # 取り込み→様邸→印刷→保存
node test/sasaoka/e2e-settings.mjs http://127.0.0.1:5180/index.html /tmp/out  # 設定・CSV・所長と担当・バックアップ・狭い画面
node test/sasaoka/e2e-estimate.mjs http://127.0.0.1:5180/index.html /tmp/out  # 見積作成：定価×0.8×長さ・同上施工費・金額だけの行・一式・2つの書式の見積書・介護保険の対象外・右に映す見積書で直す
```

ブラウザのテストは Playwright を使う（このリポジトリの依存には入れていない。場所は環境変数 `PLAYWRIGHT` で指定できる）。
`test/sasaoka/fixtures/maker-cid.pdf` はフォントを埋め込まない日本語PDF（CMapが必要な形）で、`make-cid-pdf.py`（reportlab）で作り直せる。

## 技術スタック

- フロントエンド: React 19 + TypeScript + Vite（マルチページ）+ Tailwind CSS 4（GitHub Pagesでホスティング）
- グラフ: Recharts
- データ保存: **この端末のブラウザのlocalStorageにのみ保存**（サーバー・アカウント不要）
- ホスティング: GitHub Pages（静的サイトとしてビルドして配信）

サーバー・データベース・APIキーは一切使用しない。アカウント登録やログインも不要で、開いた瞬間から使える。

## セットアップ

**前提:** Node.js 20+

1. 依存関係をインストール
   ```
   npm install
   ```
2. 開発サーバーを起動
   ```
   npm run dev
   ```

環境変数の設定は不要（Firebase等の外部サービスを使わないため）。

## データの保存場所と制約

- すべてのデータ（体重・食事・サプリ・健診記録など）は、開いているブラウザの `localStorage` に保存される
- **別の端末・別のブラウザ・シークレットウィンドウでは、記録したデータは見えない**（この端末のこのブラウザだけのデータ）
- ブラウザの「閲覧データを削除」操作や、ブラウザの再インストールでデータは消える
- 設定画面の「データをエクスポート」でJSON/CSVとしてバックアップ可能。週1回程度のエクスポートを推奨

複数端末での同期や、AIによる食事テキストの自動解析（栄養素の自動入力）を使いたい場合は、Firebase等のバックエンドを別途用意する構成に戻すことも可能（過去のコミット参照）。

## 自動デプロイ（GitHub Actions）

`main` ブランチへのpush時に `.github/workflows/deploy.yml` がビルドしてGitHub Pagesに公開する。

初回のみ、以下を手動でセットアップする。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更

これだけで、以降は `main` へのpush、または GitHub の Actions タブから `workflow_dispatch` で手動実行するとデプロイされる。
公開URLは `https://<GitHubユーザー名>.github.io/<リポジトリ名>/`。

## 実装範囲（MVP）

含む: 体重・体組成記録+推移グラフ、食事記録（テキスト入力→項目分割→手動確認）、よく食べるメニュー、間食管理、筋トレ記録、サプリ管理+重複警告、健診データ入力+前年比、ホームサマリ+改善提案（最大3件）、JSON/CSVエクスポート。

見送り（次フェーズ）: 食事内容のAI自動解析（栄養素の自動推定）、AIアシスタント自由対話、献立提案の高度化、週次レポート自動生成、健診前モード、音声/写真入力、目標体重に基づく自動ペース計算、複数端末間の同期。

## 医療安全上の注意

本アプリは診断を行わず、体重・数値の増減について断定的な評価（「肥満です」等）はしない。
症状トリガー（胸痛・息切れ・動悸・失神・浮腫）が入力された場合は必ず受診相談を促す。
薬・サプリの中止を指示することはなく、医師の指示を常に優先する。
