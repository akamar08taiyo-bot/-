# お金系バズ動画リサーチ → 企画ネタ

お金系・NISA系の発信者（がまぐち夫婦、もりげ、リベ大など）で「いま伸びている動画」を根拠つきで調べ、
共通点を抜き出し、ユーザーがそのまま作れる企画案に落とす。

成果物はレポート1本（Markdown）。中身は次の5つ。
1. バズ動画リスト（タイトル原文・チャンネル・公開年月・再生数と出典）
2. 共通点（タイトルの型・サムネ・冒頭フック・構成と尺・トピックと時期）
3. 時期ネタ（直近の需要の山と、これから来る制度変更・季節イベント）
4. 企画案（長尺・ショート。書き方は `references/plan_format.md`）
5. 制作時の注意と、データの限界

## 1. 依頼の大きさを決める

| 依頼の例 | 進め方 |
|---|---|
| 「幅広く調べてネタ出し」「直近2年のバズ」 | フル調査：7観点を並列で（2.） |
| 「前回から何が伸びた？」「今月のネタ」 | 差分調査：前回レポートの日付以降に絞り、3〜4観点 |
| 「〇〇チャンネルを分析」「この動画はなぜ伸びた？」 | ピンポイント：対象＋似た2〜3チャンネル。動画は中身も見る |
| 「〇〇のテーマで企画だけ」「タイトル案を10個」 | 企画のみ：調査は確認程度。`references/patterns.md` と過去レポートを根拠に4.へ |

- 期間の指定がなければ、フル調査は直近2年、差分調査は前回レポートの日付以降。
- 作業フォルダに過去のレポート（`reports/`）や調査メモ（`research_notes/`）があれば最初に読む。前回からの変化を書けるし、同じ企画を出し直さずに済む。
- 聞き返すのは結果が大きく変わる点だけ（例：YouTube以外も含めるか）。それ以外は既定で進め、レポートの冒頭に前提として書く。

## 2. 調べる

### 道具と予算を最初に決める
環境によって使える道具が大きく違い、回数やお金の上限もある。初回のフル調査では、途中で検索の上限と Gemini の残高の両方が尽き、調べ残しが出た。最初の数分で確かめて、配分を決めてから動く（詳しい使い方と curl の例は `references/tooling.md`）。

- **WebSearch**：主力。検索結果の要約に、ユーチュラなど集計サイトの再生数が載ることが多い。ただしセッション全体で約200回が上限で、サブエージェントとも共有する。7観点なら1観点20回前後に抑え、残りは予備にする。
- **WebFetch・curl**：クラウド環境では youtube.com や集計サイトがほぼ遮断されていた（EGRESS_BLOCKED）。1回試して駄目なら使わない。
- **Gemini API**（届く環境なら）：**有料で、ユーザーの前払いクレジットから引かれる。** 初回の調査では7つのサブエージェントが並行して使い、前払い残高を超えて約2,500円のマイナスになってから気づいた。だから:
  - 使う前に、ユーザーに「Gemini APIを使うこと・何に使うか・上限（呼び出し回数と金額の目安）」を伝えて許可をもらう。許可がなければ WebSearch だけで進める。
  - 残高はこちらから見えないので、呼び出し回数と応答の `usageMetadata`（トークン数）を数えておく。上限の半分と上限に達した時点、終わった時点で、ユーザーに使った量を短く報告する。
  - サブエージェントには、それぞれの呼び出し回数の上限を渡す（例：1エージェント5回まで、動画を見るのは全体で3本まで）。
  - URL読み取り（url_context）：YouTubeの動画ページ、チャンネルの動画一覧、ユーチュラのページから、表示どおりの再生数と「◯か月前」が取れた。再生数集めではいちばん効率がよい。
  - 動画を直接見る：画面の文字・冒頭フック・構成・口調が分かる。重い（28分の動画で約16万トークン）ので、冒頭3分に切り、1観点1〜2本までにする。
  - Google検索つき回答：手がかりにとどめる。再生数や年を取り違え、出典URLの半分ほどは無関係か404だった。
  - 402（クレジット切れ）が返ったら以後は使わず、ユーザーに伝える。429（混雑）は少し待って1回だけやり直す。
- 上限で止まっても困らないよう、大事な観点（下の1・3・6・7）から先に進め、メモはこまめに保存する。

### 観点の分け方（フル調査）
互いに重ならない7観点。サブエージェントが使えるなら1観点1エージェントで同時に走らせる（指示文の型は `references/researcher_prompt.md`）。使えないなら 1→3→6→7→5→2→4 の順に自分で進める。

1. 夫婦・家計・FIRE系（がまぐち夫婦、もりげ〈セミリタイア目指す夫婦〉ほか）
2. アニメ・漫画・合成音声の解説系（サラタメ、フェルミ漫画大学、ずんだもん・ゆっくり系ほか）
3. 顔出し・講義系の新NISA・投資・節約（リベ大、中田敦彦、バフェット太郎、高橋ダン、ちょる子ほか）
4. 経済ニュース・対談メディア（後藤達也、ReHacQ、PIVOT、NewsPicks、テレビ局のニュースほか）
5. 実数公開系（街頭インタビュー、資産・運用成績公開、家計簿公開、年金生活vlog）
6. ショート（YouTubeショート・TikTok・Instagramリール）と各SNSの規約
7. 時事・制度カレンダー（期間中の需要の山と、この先の制度変更・季節イベント）

チャンネル名は出発点にすぎない。調べる中で伸びている新顔を見つけたら加える。

### 記録のルール
企画はこの記録の上に建てる。間違った「バズ」を拾うと、その企画の制作がまるごと無駄になる。
- タイトルは原文のまま。公開年月、再生数とその出典・確認日、URL を残す。
- 「バズ」は再生数の大きさに加え、チャンネルのふだんの再生数（直近の中央値）に対する倍率でも見る（目安3倍以上）。倍率はチャンネルの大きさに左右されず「ネタの強さ」を表すので、小さなチャンネルが真似するときの物差しになる。
- 数字やタイトルを作らない。確かめられないものは「未確認」、出典で食い違うものは両方を書く。
- 期間外の動画は「期間外（参考）」と明記する。
- 2026年8月24日からYouTubeの再生数の数え方が変わった（再生が始まれば1回）との報告がある。この日をまたいで比べるときは、それ以降の数字を割り引いて見る（要確認）。

## 3. 共通点を抜き出す
2つ以上のチャンネルで繰り返し出てくるものだけを「型」と呼ぶ。1本だけの当たりは偶然かもしれない。
`references/patterns.md`（これまでに見つかった型の一覧）と照らし、「今回も効いている型／新しく出てきた型／弱くなった型」に分ける。

比べる軸:
- タイトル：数字・金額・〇選、【】タグ、年収・年代・家族構成の名指し、損失回避の言葉、比較、年号・最新版、界隈ことば、感情のセリフ引用
- サムネ：文字量、左右の分け方、顔・キャラの表情
- 冒頭フック：最初の3〜30秒で何をするか（本音の代弁、数字の連打、結論先出し、人生の物語から入る）
- 構成と尺：シミュレーション、掛け合い、ランキング、実数公開、Q&A
- トピックと時期：何が、どの出来事のときに伸びたか

初回調査では、型そのものより「数字の出どころ」（誰の・いつの数字か。実在の人の年金額、本人の口座画面、出たばかりの公的統計）が外れ値を分けた。型を数えるだけでなく、ヒットごとにその数字の出どころも書き留める。

なぜ伸びたかは、観察した事実と推測を分けて書く。

## 4. 企画に落とす
書き方は `references/plan_format.md`（ユーザーが渡してくれた形式がもと）。指定がなければ長尺5本・ショート5本。
1本ごとに次の2つを添える。ユーザーが採るかどうかを決める材料になるため。
- **根拠**：借りたバズ動画と型（チャンネル・タイトル・再生数）
- **今出す理由**：時期ネタとのつながり（なければ「定番」）。`patterns.md` の「6.」に2027年10月までのカレンダーがある（古くなっていたら調べ直す）

企画の軸は、公的統計の最新版を、条件を明示した自前の試算に変え、視聴者が自分の位置を確かめられる形で見せること（`patterns.md` の「0. 結論」）。AIアニメで作るユーザーにとって、伸ばす工夫と収益化を守る工夫が同じ方向になる。

あわせて:
- 実体験・実録・資産公開の型は、ユーザーにそのデータが本当にあるときだけ使う。なければ「仮に〜したら」のシミュレーション、公的統計の「平均」との比較、公開されている調査結果の解説に置き換える。架空の体験談や運用実績は作らない（ユーザーの money-shorts のルールでも禁止）。
- 過去のレポートやユーザーの手持ち企画（`references/patterns.md` の最後）と同じ企画は出さない。似るときは切り口の違いを書く。
- ショート案は money-shorts でそのまま作れる形にする（`plan_format.md` の最後）。

## 5. お金ジャンルで守ること
企画の段階で入れておくと、台本・制作での手戻りが減る。
- 断定しない（必ず増える・損しない・絶対儲かる）。節約の「絶対買わないモノ」のような生活の言い切りは構わない。
- 個別の銘柄・商品・会社を勧めない（金融商品取引法の投資助言にあたるおそれ）。
- 仮定の計算は条件を出す（「仮に年5%」「税・手数料は考えない」）。デメリットも一言入れる。
- 制度の数字は一次情報（金融庁・国税庁・厚生労働省・日本年金機構など）で確かめ、時点を書く。
- アフィリエイトにつなぐ企画はPR表記が要る（ステマ規制）。表記は概要欄の冒頭か画面に出す。大量のハッシュタグの末尾に埋もれる形では足りない。TikTokは投資サービス・クレジットカードの宣伝ができない。
- AIで量産するなら、YouTubeの収益化ポリシー（2025年7月の「量産型・繰り返し」コンテンツの明確化）に触れないよう、独自のキャラ・データ・解説を入れる。2026年1月以降、抑揚や間を調整していない合成音声、フリー素材だけ、同じテンプレートの使い回しのチャンネルで収益化停止が相次いだと報じられている（報道ベース）。企画ごとに構成や見せ方を変える案を出す。

## 6. まとめて届ける
レポートの形:

```
# <タイトル>
（前提：対象期間・対象・調べた日・データの限界を3〜4行）
## 結論（効いている型と、すぐ作るべき企画を5行以内）
## バズ動画リスト（表）
## 共通点（タイトル／サムネ／フック／構成と尺／トピックと時期）
## 時期ネタカレンダー
## 企画案（長尺・ショート）
## 制作時の注意
## 出典
## 付録：パターン集の更新案（新しい型・弱くなった型・代表例）
```

- 作業フォルダの `reports/<タイトル>.md` に保存し、調査メモは `research_notes/<タイトル>/` に置く。前回と同じタイトルにしない（上書きを防ぐため）。
- ファイルを送る道具（SendUserFile など）があればレポートを送る。
- 付録の「パターン集の更新案」は、次回の比較の土台になる。ユーザーが望めば `references/patterns.md` に反映してスキルを更新する。
- 会話では、結論と「次に作るなら」の上位3案だけを短く伝える。
