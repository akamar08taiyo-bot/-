# 機能・連携・権限の棚卸し

## 適用条件
ユーザーの明示的な `/xfer-plugins-plugin-management` 呼出を待つ。別スキルから本文を読んで自動呼出制限を迂回しない。呼出自体は公開・送信等の個別操作を一括承認するものではない。

## 入力
対象：機能・連携・権限の棚卸し。
ユーザーの目的、利用可能な素材、対象範囲、出力形式、必要な精度、許可された操作。
不明な確定値は推測しない。安全に仮定できる形式上の条件だけを明示して進める。

## 依存と実行可能性
該当する検索・ファイル・コード・画像・編集・スケジューラーの手段。スキル文だけでは機能自体は追加されない。
接続・権限・対象の存在を先に確認する。登録スキルがあることと、その外部機能が実行できることは別である。

## 実行手順
1. 目的、対象範囲、正本、許可された操作、完了条件を確認する。必要なら [共通実務手順](references/workflow.md) を読む。
2. 現在の機能と接続状態を調べる。
3. 不足する機能に必要な最小連携を選ぶ。
4. 接続・解除・権限変更は承認後に実施する。
5. 以下のチェックを実施し、問題があれば最小修正して再検証する。重要な外部操作や破壊的操作は実行前に承認を確認する。
6. 成果物を実際に確認し、実施結果・根拠・未実施事項を分けて報告する。

## 出力契約
目的に対応した回答または成果物、根拠、実際の操作・検査、未確認点と必要な追加環境。
結果報告には「対象／使用した根拠／実施したこと／検査結果／未確認または未実施」を含める。不要な秘密値や元データ全量を報告しない。

## 完了チェック
- [ ] 登録済みと接続済みを区別。
- [ ] 秘密値を列挙しない。
- [ ] 依頼条件、固有名詞、数値、日付、参照先を正本と照合した。
- [ ] 実際に確認した範囲と、実行環境不足などによる未確認を分けた。
- [ ] 外部送信、公開、支払、削除、権限拡張を無断で実行していない。

## 停止・代替
認証不足、対象不存在、重大な数値不一致、機密漏洩の疑い、未承認の高リスク操作では該当操作を停止する。権限を自動拡張しない。実行できない部分は明記し、安全な設計・下書き・ローカル検査は継続する。
