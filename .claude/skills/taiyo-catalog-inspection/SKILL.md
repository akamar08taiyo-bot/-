# カタログの検品（徹底的に・まちがえない）

## なぜこのスキルがあるか（重く受け止めること）

- 2026-11-09 ユーザーの指示「カタログと商品が違ったものがあった。そこは絶対に間違わないでほしいので、徹底的に検査、確認する」。
  1回目の点検のあと、ちがっていた所の一覧（72商品・199か所）を出したら「ちょっとミスがあまりにも多すぎました。信憑性、信用が足りない。完璧にもう一度ミスがないか見直す。
  ミスの種類を見つけやすいポイントを自分で考える。20、30で検品できるようなエージェン卜や担当部隊をつけ、デプロイ公開する前には完璧に直す。時間は何時間かかってもいい」。
- 同じ日に実害が出た：「パナソニックのユクリア コンパクトシャワーチェアで、本来は肘付きのやつを見積もりに出さないといけないところを、肘なしの分で照合して型番が出てきた。
  金額を負けなければいけないような状況になった。重く真剣に受け止めてください」。原因（特定福祉用具の販売見積書の「📖 カタログから商品検索」）：
  - カタログでは肘掛けの有無が、名前の「SP」（コンパクト**SP**おりたたみN＝肘付き PN-L41321 ／ コンパクトおりたたみN＝肘なし PN-L40721）と、枠の下の機能アイコン（「ひじ掛け」が黒＝あり・灰色＝なし）でしか分からない。
  - アプリの一覧に肘掛けの有無が出ていなかった。商品名の欄に「肘付き」と打っても、その語は黙って捨てられ（商品名にないので）、品目の全部の商品が出ていた。「コンパクトシャワーチェア」のようにくっつけて打つと「コンパクト」も消えていた。
  - 直したこと：機能アイコンを全商品で読む（`src/tokutei/catalogFeatures.ts`。`.claude/skills/taiyo-tokutei-app/scripts/catalog-icons.py` で作る）・一覧／色を選ぶ欄／カタログの窓／入れた商品の欄／型番から検索の知らせに「ひじ掛けあり／なし」・
    検索で「肘付き・肘なし・ひじ掛け付・アームレスト」を使う（`catalogItems.ts` の `catalogFilter`・`armrestOf`）・使えなかった語は赤い知らせ（`unmatched`）。テスト：`catalogItems.test.ts`・`e2e-items.mjs`。
- **返事・報告は必ず日本語**（ユーザーの指示「私に説明する分は必ず日本語で説明してください」2026-11-09。英語で返した回があり「なんかあったかも」と心配させた）。

## 原則

1. **正はカタログ**（ページの絵と PDF の文字 `catalog/text.json`）。アプリの読み取り・前回の点検・自分の記憶を正としない。
2. **正解を見せない書き取り**：検品担当には、アプリの値を見せずにカタログを書き取らせ、機械（`compare.py`）でアプリとくらべる。アプリの値を見せて「合っているか」と聞くと、見せた値に引っぱられる。
   金額・TAIS の部は、行（品番｜色）だけ見せて金額・TAIS は書き取らせる。
3. **同じ所を2人（A班・B班）で、逆の順に**（同じ疲れ・同じ思い込みで同じ所をまちがえないように）。品番・色サイズと金額は必ず2人。
4. **部署（ミスの種類ごと）に分ける**：1つの担当に全部を見させない。観点は `references/guide.md`（前回の誤りの種類 1〜16。新しい種類の誤りが見つかったら必ず足す）。
5. **食い違いだけを審査**：A・B・アプリが全部同じなら合格。どれかがちがえば、審査担当（2人。割れたら3人目）が絵と PDF の文字で決める。読みにくい字（ポとボ・パとバ）は PDF の文字で決める
   （MP2000-300 の「ポール付き」は PDF の文字どおり。検品の2人とも「ボール付き」と読みちがえた）。
6. **直したら再検品**：直した所は、別の担当でもう一度、正解を見せずに書き取る。ブラウザで全商品を押す（`test/tokutei/e2e-catalog-all.mjs`）。
7. **公開は全部が終わってから**。途中で公開しない。
   コミットの前に、足した行を金額の形で grep し（`git diff --cached -U0 | grep '^+[^+]' | grep -E '[¥￥] ?[0-9]|[0-9],[0-9]{3}'`。`¥` のすぐあとに数字・3けたごとのカンマ）、**1行でも出たら commit しない**
   （2026-11-09、コメントの例にカタログの金額を2つ書いたまま commit・push した。直しは新しいコミット。履歴の書きかえは強制 push が要り、作業環境で止められる）。
8. **名前が1〜2字だけちがう商品**（SP・U型・回転・腰当付・背付き／背無し・ワイド／ミドル／コンパクト・1220／1826）は、名前だけで照合しない。機能アイコン・表の見出しも見る。

## 手順（道具は scripts/。パスは /home/user/tokutei（特定福祉用具のブランチ）と /home/user/-（住宅改修のブランチ）の取り出しを前提に書いてある）

1. `npm run -s build:tokutei`（dist-tokutei/catalog/text.json・rules.json）。
2. 介援隊：`node .claude/skills/taiyo-tokutei-app/scripts/catalog-render.mjs . <S>/insp/pages`（300dpi）→ `catalog-dump.ts . <S>/listnew`（アプリの読み取り。金額を含むのでリポジトリに入れない）
   → `python3 scripts/crops.py <S>`（商品ごとの切り抜き。1500px を超える商品は分ける）→ `python3 scripts/overlay.py <S>`（枠を描いたページ）。
3. 住宅改修：`node scripts/jutaku-dump.ts <S>/insp/jutaku/data.json` → `python3 scripts/jutaku-sheets.py <S>`（見くらべ表・枠を描いたページ）→ `python3 scripts/jutaku-machine.py <S>`（PDF の文字との機械照合。
   TOTO・マツ六の PDF の文字は scripts/maker-catalog/render.mjs の <頭>-text.json）。
4. 機械照合：`python3 scripts/machine-tk.py <S>`。
5. 担当の割り当て（`<S>/insp/assign/*.md`）を作り、Workflow で部署ごとに走らせる（結果は担当が `<S>/insp/out/*.json` に書く。返事はファイルの場所と件数だけ）。
   48人で約1千万トークン・1時間半ほど。**使用量の上限で途中で止まることがある** → `Workflow({scriptPath, resumeFromRunId})` で、終わった担当はそのまま・止まった担当だけやり直す。
   安全確認でまれに1人止められることがある（言い回しを変えてその1人だけやり直す）。
6. `python3 scripts/compare.py <S>` → `<S>/insp/compare.json`（商品ごとの食い違い）。よくある「食い違いだが誤りではない」もの（2026-11-09）：
   - 品番がカタログにない商品（バイオクッション・オーバルリンク・Mgウォーカーなど）は、アプリが注文番号を品番にしている（作りどおり）。
   - メーカー：カタログは「パナソニック」、アプリは正式の「パナソニックエイジフリー（株）」（作りどおり）。
   - 歩行器・多点杖・スロープのページには「介・購入」の印がない（種目はページで決めている）。
7. 審査（食い違いのある商品ごとに2人。絵＋PDF の文字）→ 直す（読み取りの決まり `catalogItems.ts` か、ページの書き方が特殊な商品は `catalogFixes.ts`）→ スナップショットを作り直す
   （`catalog-dump.ts … --snapshot`）→ 全テスト・`e2e-catalog-all.mjs`・`e2e-items.mjs` → 直した所を別の担当で再検品 → 0 件になってから公開。

## 2026-11-09 の結果（1回目の検品部隊 48人＋再検品 3人）と直したこと

- 介援隊：**金額は 857 品番すべてで A・B とも一致**（つるべーの金額のうしろの「～」＝設置方法で金額が変わる、だけ要注意）。**品番もすべて一致**（品番のない商品は注文番号）。
- 介援隊で直したこと（`catalogFixes.ts` の「2026-11-09 の検品部隊」。39商品・173品番）：表に色の欄がなく、色の名前が写真の横・色見本の下にしかない商品を、
  色ごとに選べるように（1つの品番に2色以上「各¥」の商品 約20・1色だけの商品 約15）。キャリーベルトのウエスト・「穴無しシート」（2行に割れていた）も。
  直したあと、別の担当2人（逆の順）が正解を見ずに書き取り直し、78件中72件で一致。残りの6件は言い方（cm）と「1つだけの色の名前をどの品番に付けるか」の読み方で、
  **写真の横に1つだけある色の名前は、その写真の品番にだけ付ける**に決めてそろえた（guide.md の17）。
  ほかに、品番ごとにちがう機能（さわやかチェア 泉II の「ひじ掛け跳ね上げ」は 8253 はね上げタイプだけ）の札を品番に合わせた（`featureBadges(p, v)`）。
- 住宅改修で直したこと（`scripts/maker-catalog/codes.py` を直して作り直し。リポジトリ `-` のブランチ claude/sasaoka-shikiri-app）：
  - TOTO：p.51「TS139CEE11」（PDF の文字の欠けで TS139CEE1 になっていた）・「タイプ番号」（品番ではない）と裏表紙の記号を外す・
    「2m：」「◆」「／」「φ35：」の付いた品番や「品番 ¥金額」が1つの字の品番も読む。品番索引（p.101・102）の「品番 ····· 掲載ページ」の行
    （前は点のある行の品番が読めず、索引の 370 品番のうち 149 に枠がなかった）。固定金具の一覧の「L型手すり (T112CL9」（品名とつながった品番）。
    略した品番（「（T114CL9R・CL10R）」の CL10R、「CL10」「CP22」）は前からの決まりどおり枠にしない（いったん T114CL10R につないだが、同じ表のほかの略した品番とそろわなかった）。
    写真の札（「写真は T112HK7R／#NW1です。」）・注記の文の中の品番は、同じページの表の行に同じ品番があれば表の行の枠だけ。
  - マツ六：**商品コードの行なのに品番の形が決まりに当たらず枠がなかった約160行**（P34NV-400-00・DX14C・EL5060-1M-NS・AF-1 など。p.24・27・59・60・61・63 はページごと）を足し、
    説明の文・注記（※適応品番）・参照の表・見本・写真の札の枠 約70を外した（押すと色の決まらない品番や、ちがう商品が入っていた）。
  - 矢崎化工：枠の位置3つ（p.12 HCT-4000 T OLG・p.37 CZG-1 BR・p.43 AA-35TS）。説明の文の中の品番（「（AA-35FT不可）」など）は枠にしない。
- **教訓**：検品の担当にわたす「参考の候補」を、アプリと同じ決まり（同じ正規表現）で作ると、アプリの見落としを担当も見落とす。候補は別の見方
  （商品コードの行・品番索引）で作る。`jutaku-machine.py` の③④がその見方。
- **教訓（再検品で見つかった、直したことで生まれた誤り）**：品番の字を直す（PDF の文字の欠けを直す・略した品番をつなぐ）と、枠の位置を「直したあとの字」で
  文字の中から探して見つからず、枠が右へずれた（TS139CEE11・T114CL10R の枠が品番の後ろ半分と金額を囲んでいた）。**枠の位置は印刷された字で測る**
  （`codes.py` の `printed`）。直したら、直した所だけの見くらべ表（`jutaku-sheets.py` を、足した・動かした枠だけの data.json で）を作り、別の担当2人に見せる。
  1回目の直し → 再検品2（226行）→ その指摘の直しと索引など → 再検品3（249行）と、0 件になるまでくり返す。
- **枠の位置は書体で測る**（再検品3）：品番の前後に日本語・金額・「（L タイプ）」・表の番号がつながった PDF の文字は、字の幅を 0.55・1 と決めて
  位置を見積もると、品番の頭や終わりの1字が枠の外に出た（約370の枠）。`codes.py` は書体（BIZ UDPゴシック）で字の幅を測り、品番が文字の頭なら左、
  終わりなら右の端にそろえる。絵の字の切れ目だけで枠を決める方法も試したが、「1」の左右のすき間が単語の切れ目と同じくらい広く、うまくいかなかった。
  確かめは `scripts/jutaku-cutcheck.py`（PDF を 300dpi で描き直した絵で、枠の端が字を切っている数。前は 371、いまは 30 で全部くっついた記号）。
- **決まりをそろえる**：同じ表の中で、ある品番には枠があり、となりの同じ形の品番には枠がない、は必ず指摘される。直すときは「その表の全部の行」で同じ決まりになっているかを見る
  （略した品番・品名とつながった品番・索引の点のある行／ない行）。
