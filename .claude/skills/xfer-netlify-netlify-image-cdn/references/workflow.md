# 実務手順と受入条件

## 着手
作業ルート、変更対象、既存のREADME・設定・ロックファイルを読む。実際の依存バージョンを正とし、APIの現行仕様を一次資料で確認する。秘密値は表示しない。
## 実装
入力検証、認証と認可、状態管理、エラー処理を明確にする。通常の数値計算はプログラムへ任せ、AI出力はスキーマ検査してから利用する。無関係な設定の更新やパッケージ追加はしない。
## 検証
型・lint・単体テスト・ビルドに加え、必要なブラウザ操作と保存・再取得を確認する。正常、空、失敗、切断、連打、権限不足を試す。モックと実接続の検証を明確に分ける。
## 変更管理
commit、push、merge、公開、デプロイ、支払、DB変更、権限拡張、パッケージ導入は承認境界を確認する。ローカル成功を本番成功としない。変更内容とロールバック方法を記録する。
