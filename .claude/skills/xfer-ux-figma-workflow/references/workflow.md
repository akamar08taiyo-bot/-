# 実務手順と受入条件

## 根拠を用意する
ユーザーの目的、実際の画面、観察結果、制約を記録する。架空の利用者像や効果数値は仮説として扱う。新規構築、部分改善、忠実再現を区別する。
## 状態を設計する
通常、読み込み、空、入力エラー、通信失敗、権限不足、成功、再試行を確認する。デスクトップと狭い画面、キーボード、文字拡大、動き低減を考慮する。
## 品質を測る
同じ画面幅・状態で参照と実装を比較する。余白、文字階層、操作対象、コントラスト、焦点移動を点検する。見た目の好みとタスク達成上の障害は分けて報告する。
## 引継ぎ
部品、状態、トークン、レスポンシブ条件、利用素材、未検証点を記録する。公開や実データ操作は試作と切り離す。生成AIが使えない場合は仕様案と明記する。
