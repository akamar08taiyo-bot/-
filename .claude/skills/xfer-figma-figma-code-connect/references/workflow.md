# 実務手順と受入条件

## 既存構造
ファイル種別とノードIDを確認し、部品・変数・スタイル・自動レイアウトを読み取る。登録済みライブラリやCode Connectの対応を再利用する。Figma操作権限がない場合は実編集済みとしない。
## 差分を小さくする
ページ、部品、アニメーション、ライブラリの仕事を区別する。既存デザインを不要に平坦化・画像化せず、状態と変数の関係を保持する。広範囲の削除や新規共有は承認を得る。
## 双方向の一致
コードからFigma、Figmaからコードのどちらかを明示する。画面幅、フォント、素材、状態をそろえて比較する。SwiftUI・FigJam・Slidesは対象固有の制約を公式資料で確認する。
## 成果確認
編集APIの成功だけでなく結果の構造と描画を確認する。シェーダーや動きは対応API、負荷、アクセシビリティを点検し、未対応部分は明記する。
