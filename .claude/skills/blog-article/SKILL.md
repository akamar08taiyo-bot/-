# ブログ記事を1本仕上げる

例: 「この動画を（自分のブログ）の記事にして、YouTubeリンクを貼って」

## 手順

1. **種類の判定とスキル選び**（ジェブ判断）: 記事の種類（解説・レビュー・事例）と掲載先ブログを確認する。掲載先ごとのルールが `ai-ecosystem/knowledge/clients/<ブログ名>.md` にあれば読む。
2. **素材を読む**: 動画なら文字起こしを用意する（人間から受け取る、または YouTube の文字起こし）。動画そのものを見て確かめる必要があるときは `ask-other-ai` で Gemini に回す。
3. **構成を作る**: 見出し（H2/H3）案と、各見出しで言うことを1文ずつ。jeb-judge に段取り（plan）として判定させる。
4. **調べながら図を作る**: 事実はWeb検索で裏を取り、出典URLを控える。図が必要な箇所は、画面の切り出し（ffmpeg で静止画）か、`ask-other-ai` で Codex に描かせる。図の中の文字は `judge-image.mjs` で確認。
5. **SEO**: タイトル（32字前後、主キーワードを前半に）と概要文（120字前後）を3案ずつ出し、1つに決める。
6. **本文を書く**: 文章ルールどおりに書く。YouTube リンクと出典を入れる。
7. **推敲**: `japanese-editor` サブエージェントで日本語を直す。
8. **検品**: `jeb-judge` に依頼文・下書きのパス・元資料を渡す。元資料（文字起こし）と数字・固有名詞を照合させる。FAIL なら直す。
9. **下書き**: `ai-ecosystem/output/<ブログ名>/<日付>-<スラッグ>.md` に Markdown で保存（フロントマターに title / description / date / tags / youtube）。ブログのリポジトリがある場合はそこにブランチを切って置く。
10. **人間の最終確認**: 下書きのパスかプレビューURL（`web-publish` スキル）を渡し、公開は人間の確認後に行う。

## メモ

- 書いていて見つけた不自然な言い回しは `obsidian-memo` で辞書に足す。
- 公開した記事は `ai-ecosystem/knowledge/sns/x-ideas.md` に「告知ネタ」として1行残す。
