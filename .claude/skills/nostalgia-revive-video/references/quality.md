「作って終わり」にしない。各段階で**機械の検査**と**自分の目（Read で画像を見る）**の両方を通す。耳で聞けない環境では、Gemini に聞かせる・グラフで見る、で代える。

## 1. 画像
1. `img_sheet.py` で12枚ずつの一覧を作り、**全部 Read で見る**。人物の取り違え（服の目印で確認）、時代違い、文字・ロゴ、縁や日付の刻印、手指の崩れ。
   - 一覧の縮小表示では小さなロゴは見えない。**店の棚・箱・看板・服・車が写るカットは `zoom_grid.py <ID>` で元の解像度のまま6分割して全部見る**（実例：模型店の写真に、模型の箱・塗料缶・塗料瓶の星マークが計10か所以上あった）。ぼかす範囲は `zoom_grid.py <ID> --box ...` の1%目盛りで決め、手・持ち物・顔にかからないよう細かく分ける。直したら `--fixed` で確かめる。
2. `check_images.py` で Gemini にも検査させる（work/imgcheck.json）。severity が major のものは作り直し、minor は拡大して判断。**severity だけを見ない**：実例では、模型の箱の「星マークのロゴ」を text_or_logos に挙げながら severity は "none" だった。文字・ブランド・縁の指摘は全部、拡大して確かめる（スクリプトは指摘があれば表示する）。検査は元の画像に対して行うので、fixes.json でぼかした所も指摘される（ぼかしで足りているかは目で確かめる）。
   - **作り直した画像は必ずもう一度検査し、拡大して見る。** 実例：ロゴを消すために作り直した模型店の写真に、別の箱と塗料缶で同じロゴが残り、一覧の縮小表示では見落とした（冒頭の「写真が動き出す」カットとサムネイルに使う大事な絵だった）。
3. 直し方：
   - 作り直し：`gen_scenes.py --only ID --extra "..."`（references/prompts.md の 3.）
   - ぼかす：`fixes.json` の `"S08": {"blur": [[x0, y0, x1, y1, 半径], ...]}`（画像に対する割合。小さい文字は半径5〜9、大きいロゴは12前後）
   - 切り取る：`"crop": [x0, y0, x1, y1]`（カメラが動く範囲。人物違いを画面の外に出す、場違いなテレビを外す）
   - 日付を描き込む：`"stamp": {"text": "'97 8 3", "x": 0.77, "y": 0.81, "rot": 4, "scale": 1.2}`
   - 差し込み：同じ画像を別の演出で使う `img="S03"`（例：電子ペットのおばけを、液晶が見えるカットに描く）
4. 色を部分的に塗り替える（白髪にする等）は不自然になりやすい。比べて悪ければ元に戻し、作り直しを待つ。
5. 一覧の目安（実例）：57枚中、作り直し7枚・ぼかし8枚・差し込み1枚・削除1枚（場違いな携帯ゲーム機が出たカット）。

## 2. 動き（Veo）
- 1本試して、コマを4枚ほど抜いて一覧で確認（`ffmpeg -ss 0.2 / 2.5 / 5.0 / 7.6 -frames:v 1`）。顔の崩れ・手の増殖・文字の出現・急なカメラの動きがないか。
- **最初の3秒は0.5秒刻みでも見る。** 物が増える・形が変わるのは最初の1秒で起きることが多い（実例：手に持ったおもちゃの車が0.6秒で2台に増えた）。4枚の一覧だけでは「最初から2台持っていた」ように見えて見落としやすい。
- 群衆・たくさんの子どもが写るカットは崩れやすい。静止画のままにする判断も大事（全カットを動かす必要はない）。
- 写真が動き出すカットでは、プリントの間は動画の最初のコマが映る。`render.py --at ID:1 ID:3.5 ID:7` でプリント→色が戻る→動き出す、の3点を確かめる。
- 不採用のクリップは assets/clips/ に置かない（置くと render.py が使う）。

## 3. 声
- `gen_voices.py` の文字起こし確認で、台本以外の言葉（指示文の読み上げ・英語）が入っていないか。結果は work/voices_report.json。
- `gen_voices.py --age-check` で年齢・性別の印象と役との合い方（10点満点）、同じ人物の声がそろっているか。7点以下は声を替えて候補を聞き比べる。
- 語尾・固有名詞の読み（「しような」が「しようぜ」になる等）は文字起こしで確かめる。
- 人の耳で確かめてほしい箇所として、セリフ全部を報告に書く。

## 4. 環境音・効果音
合成した音が「それらしく聞こえるか」を**目隠しテスト**で確かめる：音を番号だけのファイルにして Gemini に聞かせ、何の音に聞こえるかを答えさせる。
```
添付の音声ファイルは番号順に並んでいます。それぞれ何の音に聞こえるかを、先入観なしで答えてください。
番号 | 何の音に聞こえるか（できるだけ具体的に） | 本物らしさ(1-10) | 耳ざわりな点（キンキンする、ノイズっぽい、不自然な繰り返し、急に大きい、など）
最後に、メロディーがあるファイルがあれば、その曲名に心当たりがあるかも書いてください。
```
- 曲名の心当たりも聞くと、旋律の確認の手がかりになる（ただし当たらなくても旋律が間違いとは限らない。旋律は資料の階名で照合するのが本筋）。
- **1秒に満たない短い音は聞き分けが当てにならない**（実例：グローブの捕球音を「オルゴールのアルペジオ」と答えた）。sfx_test.py は短い音を3回くり返して聞かせる。結果は目安にとどめ、最後は人の耳で確かめてもらう。
- 複数の音を1回でまとめて聞かせると、番号の対応が崩れて答えが抜ける。1ファイルずつ聞く（sfx_test.py はそうしている）。
- 本物らしさが低い音は sfx.py で直すか、音量を下げて背景に回す。
- 実例（電池の夏 v2）：テレビの声（合成の母音）→「機械の声」3点 → **TTS のアナウンサー（天気予報・野球実況）をテレビのスピーカー越しにしたら9点**。夜の虫（純音）→「電子アラーム」→ 狭い帯域の雑音とゆらぎを混ぜ、数を増やして遠近をつけたら単独で「スズムシ」8点。公園（合成の鳥）→「電子玩具」4点 → 鳥を外して風に。金属バット（響きが短い）→「竹を叩く音」→ 響きを長くして「金属のベル」7点。人のざわめき（合成）は少人数だと「ダミ声」に聞こえる → 人数を増やして小さく。可能なら TTS で短い歓声を数本作って遠くに重ねる方が自然。
- 人の声・テレビ・ラジオのように「言葉」が聞こえる音は、合成より TTS（gen_voices と同じ構造化プロンプト）で作り、`assets/sfx/<名前>.wav` に置く。sfx.py の proj_audio() がそれを読み、スピーカー越し・遠くの音に加工する（tv_morning_voice / tv_baseball_voice）。

## 5. 確認用の静止画・テストコマ
- `render.py --stills`：各カットの代表コマ（写真が動き出すカットは色が戻った後）を work/stills/ に。一覧にして全部見る。
- `render.py --at P02:1.2 P02:4.0 S12:7 ...`：気になる瞬間（プリントの状態、キャプション、ドット絵、題字、エンドカード）を1枚の一覧に。
- 見る所：文字がはみ出していないか・読めるか、キャプションと日付が重ならないか、ドット絵が液晶に収まっているか、カメラの動きで画像の端が出ていないか、ぼかしが自然か。

## 6. 音のミックス
- mix.py の表示：I（全体のラウドネス、-14 LUFS 前後）、LRA（ラウドネスの幅、3〜7 LU なら落ち着いて聞ける）、TP（トゥルーピーク、-1.0 dBTP 以下。-2 前後が安全）。
- `loudgraph.py out/<名>_audio.wav work/loud.png`：3秒窓のラウドネスの推移。**赤丸（2秒で+8LU以上の急な上昇）はゼロにする**。
  - よくある原因と直し方：転換で曲が切れて無音の谷ができ、次の曲で跳ね上がる → `music_preroll` で手前から重ねる／チャイム・雷が大きい → sfx の dB を下げる／遠くの呼び声で周りを下げてしまう → far=True／短い曲が区間の途中で終わる → 最後まで流す（mix.py が自動で判断）。
- `spectro.py out/<名>_audio.wav work/spectro.jpg`：パートごとのスペクトログラム。高い帯域が帯のように続く（キンキン）、低い帯域が強すぎる（ボワボワ）、同じ模様の繰り返し（ループが分かる）を探す。

## 7. 完成ファイル
`finalize.py` の検査（work/check.json）：
- 解像度・fps・長さ（scenes.json の total と ±1.5秒）
- ラウドネス：-14 ±1 LUFS、TP ≦ -1.0
- 急な音量の上昇なし（sudden_loudness が空）
- 意図しない黒コマなし（blackdetect。冒頭・末尾のフェードは除く）
- セリフの音声ファイルがそろっている
- 一覧画像 work/final_sheet.jpg（12秒ごとのコマ）を Read で見て、実際にエンコードされた絵を確かめる
- `finalize.py --small` で28MB以下のプレビュー（アプリで送れる大きさ）

## 8. 視聴者目線のレビュー（AI）
クレジットに余裕があれば、完成動画（またはプレビュー）を Gemini に見せて、視聴者として感想と離脱しそうな所を聞く。長い動画は区間に分けて添付する（ファイルの大きさに注意）。
```
あなたは、このジャンル（AIで過去を蘇らせたノスタルジー動画）をよく見る視聴者です。動画を見て答えてください：
1. 最初の15秒で続きを見たくなったか。理由。
2. 懐かしい・心が動いた瞬間（時刻と理由）
3. 退屈・違和感・不自然に感じた瞬間（時刻と理由。AIっぽさ、絵の崩れ、音の違和感を含む）
4. コメント欄に書きたくなること
5. 改善案を3つ
```
クレジットが尽きているときは、できなかったことを検証レポートに書き、補充後にやることとして残す。

## 9. 検証レポートの型（`検証レポート.md`）
```
# 検証レポート「<題名>」
## 0. 結論（合格／条件つき合格／要修正。理由を1〜3行）
## 1. 技術検査（表：項目／基準／結果／判定）… 解像度・fps・長さ・ラウドネス・TP・LRA・急な上昇・黒コマ・容量
## 2. 映像（一覧画像の確認結果、直した箇所、残っている箇所）
## 3. 音（ラウドネス推移のグラフ、スペクトログラム、目隠しテスト、声の判定）
## 4. 権利・表記（ロゴの処理、商標の表記、旋律の出典、AI開示）
## 5. 人の目・耳で確かめてほしい所（時刻つき）
## 6. 未達と、次にやること（費用の見積もりつき）
```
実例は assets/example/検証レポート_v2.md。

## 10. レンダリングが偏って遅いとき
写真が動き出すカット・動画クリップ・雨のカットは1コマが重い。全体を workers 個に等分すると、重い区間を受け持った1本だけが遅れて最後まで残る。
- render.py は既定で workers×3 個に細かく分けて、空いた workers が次の区間を受け持つ（偏りが出にくい）。
- 古い分け方で1本だけ遅れたとき：その worker（python）を PID で止める → `ffprobe -count_frames` で出来上がったコマ数 N を数える → 残り（開始+N 〜 終わり）を `render.py --frames a b` で2〜4本に分けて並列に → concat のリストに順に並べて `ffmpeg -f concat -c copy`。止めた worker の ffmpeg は入力が途切れると正しく書き終える。
