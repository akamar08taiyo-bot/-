# 蘇らせ動画スタジオ（nostalgia-revive-video）

1枚の「古い写真」から、ある年・ある季節の思い出を蘇らせる、見ていて落ち着く動画を作る。
画像は Gemini で生成し、動き（カメラ・光・雨・写真が動き出す演出）は Python で1コマずつ描く。必要なら人物の動きを Veo で付ける。
音は、BGM を Lyria、声を Gemini TTS で作り、環境音（セミ・ひぐらし・風鈴・雨・踏切・祭り…）は**コードで合成**する（権利の心配がない）。

実例：「電池の夏 ― 1997」（1997年の夏休み・ミニ四駆と電子ペット・親友との別れ・告白・おばあちゃんのお小遣い。12分＝物語7分＋環境音5分、59カット）。
企画書・分析レポート・検証レポート・概要欄・固定コメントの実物は `assets/example/`、絵コンテの実物は `assets/example_storyboard.py`。迷ったらそれを手本にする。

## 0. まず決めること（1回でまとめて聞く）
ユーザーが言っていなければ、次をまとめて1回だけ聞く。「任せる」と言われたら、下の既定値で決めて最初に一言伝える。

| 項目 | 既定値 | 理由 |
|---|---|---|
| 時代・季節 | 依頼の年代で「流行が重なった年」の夏 | 例：1997年はミニ四駆の第2次ブームとたまごっちブームが重なる。年は**出典つきで裏を取る** |
| 絵柄 | 写実（35mmカラーネガ風） | 「蘇らせた」系で再生数を取っているのは写実。アニメ調はやさしい物語向き |
| 長さ | 物語6〜7分＋環境音パート5分 | 物語だけなら参考作どおり3〜5分。長時間視聴が目的なら環境音パートを足す（1時間版はこのパートを延ばす） |
| 動き | 静止画＋カメラ移動＋光の粒など。Veo は要所だけ | Veo は人物が動いて一気に「蘇る」が、費用がかかる |
| 予算 | 見積もりを先に伝え、了承を得てから使う | API の前払いクレジットは途中で尽きることがある |

**費用の目安**（Gemini API、2026年の目安。正確には公式料金を確認）：画像 1枚 約$0.13（3 Pro Image）×60枚＋作り直し ≈ $10／Veo 3.1 Lite 1080p 8秒 ≈ $0.64×45本 ≈ $29／Lyria・TTS・解析は少額。
→ 合計を先に伝える。クレジットが尽きたら「6. 失敗したとき」の代替で最後まで仕上げ、何が未達かを報告する。

## 1. 道具の準備
```bash
pip install scipy numpy pillow                       # ffmpeg / ffprobe も必要
python3 scripts/new_project.py <作品フォルダ>          # 絵コンテの見本・概要欄の型・空の修正ファイル・素材フォルダ
bash scripts/setup_fonts.sh <作品フォルダ>/assets/fonts  # 明朝体（しっぽり明朝、OFL）
export PROJ=<作品フォルダ>                             # すべてのスクリプトはこの作品フォルダを読む（なければ今のフォルダ）
```
API キー：クラウド環境で generativelanguage.googleapis.com にキーが自動で付くなら不要。ローカルでは `GEMINI_API_KEY` を環境変数に入れる（scripts/gapi.py がヘッダーで送る。キーを表示・出力・コミットしない）。

作品フォルダ：`storyboard.py`（絵コンテ）→ `scenes.json`（全スクリプトが読む正本）、`fixes.json`（画像の修正）、`description_template.txt`（概要欄）、`assets/{chars,img,clips,music,voice,overlay,fonts}/`、`out/`、`work/`、`research/`。

## 2. 手順（この順番）
コマンドはすべて `PROJ=<作品フォルダ>` で、`scripts/` から呼ぶ。

1. **リサーチ**（references/research.md）
   - 参考動画は URL を Gemini に直接読ませる：`gem.py --youtube URL --start 0s --end 300s --prompt-file p.txt --out research/v.md`。**読めるのは冒頭5分程度まで**（以降は 500）。長さは終わりの区間を見せて確かめる（検索結果の長さは間違っていることがある）。
   - 同ジャンルの一覧・再生数・記事・固定コメント：`gsearch.sh p.txt out.md`（Google 検索つき、再試行あり。出典は .grounding.json）。
   - **YouTube のコメント本文は取れない**。特定のコメントを参考にしたいと言われたら、本文を貼ってもらう（取れなかったことは正直に伝える）。
   - 結論を `分析レポート.md` に：上位作の型（古写真→カラー→動く、1カット約12秒、左下に日英キャプション、ナレーションなし）、自作の差別化、コメントで語られる「あるある」。
2. **企画**：コンセプトを一行で（例「夏休みは、単三電池でできていた。」）。枠構造（現在の大人が古い品を見つける→過去→現在）、章（朝・午後・夕方・夜・晩夏・別れ）、章の入口に「写真が動き出す」、後半に環境音パート。時代考証は出典つき。ユーザーの追加要望（場面・人物・小物）をどのカットに入れたかを書く。`企画書.md` に残す。
3. **絵コンテ**：`storyboard.py` を書き換えて `python3 storyboard.py`（項目は references/storyboard.md、指示文の型は references/prompts.md）。`絵コンテ.md` で流れと尺を確かめる。
4. **人物の設定画**：`gen_chars.py`（3方向の写真シート。大人の姿は子どもの設定画を参照）。並べて見て、顔・髪・服の目印がそろっているか。
5. **全カットの画像**：`gen_scenes.py --workers 5` → `img_sheet.py` の一覧を**全部 Read で見る**（店・箱・看板が写るカットは `zoom_grid.py` で元の解像度でも）→ `check_images.py`（Gemini に文字・ロゴ・ブランド・時代違い・縁・破綻を検査させる）。直し方は `gen_scenes.py --only ID --extra "..."`、または fixes.json のぼかし・切り取り（references/quality.md）。
6. **動き（任意・費用あり）**：`gen_clips.py --dry` で本数と見積もり → 了承後 `gen_clips.py`。まず1本で試す。
7. **BGM**：`gen_music.py`（Lyria）。作れないときは `synth_music.py --box M2 --amb M5`（オルゴール・アンビエントピアノを作曲）。
8. **声**：`gen_voices.py`（英語の構造化プロンプト＋文字起こしで台本どおりか自動確認）→ `gen_voices.py --age-check`（年齢・性別の印象と役の合い方）。合わない声は候補を作って聞き比べ、人物ごと替える。
9. **小物と音の確かめ（任意）**：電子ペットの液晶などは `detect_lcd.py ID --seed x y` で位置を取り、ドット絵（オリジナル）を overlay で描く。合成した環境音は `sfx_test.py --blind ...` で Gemini に1つずつ目隠しで聞かせ、何の音に聞こえるかを確かめる（合成の虫・人の声は電子音に聞こえやすい）。テレビ・ラジオなど**言葉が聞こえる音は TTS で作って** `assets/sfx/` に置く（references/storyboard.md の 7.）。
10. **確認用の静止画**：`render.py --stills` と `render.py --at P02:1.2 P02:4 S12:7 ...` を Read で見て直す。何周でも。
11. **映像**：`render.py --workers 4`（細かく分けて並列。4コアで12分の1080p に約45〜60分）。あとから数カットだけ直すときは、そのカットの範囲を `render.py --frames a b` で描き、`splice.py` でコマ単位に差し替える（全編を描き直さない）。
12. **音**：`mix.py`（BGM・環境音・効果音・セリフを時刻どおりに並べ、セリフ中は周りを下げ、ゆっくり効く平準化で -14 LUFS／-2 dBTP 前後に）→ `loudgraph.py` で赤丸（急な上昇）ゼロ、`spectro.py` で中身を確認。
13. **仕上げと検査**：`finalize.py`（結合・字幕・概要欄・サムネイル・自動検査・一覧画像・540pプレビュー）→ 一覧画像 work/final_sheet.jpg を見る → `finalize.py --small`（28MB以下の360p、アプリで送れる）。クレジットがあれば `gem.py --video <プレビュー> --low` で Gemini に完成動画を見せ、視聴者目線のレビューをさせる（references/quality.md の 8.）。
14. **納品**：本編 mp4（1080p）、小さいプレビュー、サムネイル、概要欄、固定コメント案、字幕、`検証レポート.md`（型は references/quality.md）。人の耳・目で確かめてほしい箇所（セリフ、チャイムの旋律、合成した環境音、細かいロゴ）を時刻つきで添える。YouTube の「改変または合成されたコンテンツ」の申告をオンにするよう伝える。

## 3. 守ること（理由つき）
- **実在のロゴ・商品名・キャラクターを画面に出さない。** 生成画像には、模型の箱に実在メーカー風の星マーク、車のエンブレム、アーケードの実在ゲーム名、靴の実在メーカー風ラインなどが勝手に出る。全カットを拡大して確かめ、ぼかす・外す・作り直す。**作り直した画像は必ずもう一度検査する**（実例：ロゴを消すために作り直した冒頭の模型店の写真に、星マークが10か所以上残っていた）。画面の中のキャラクターは**オリジナルのドット絵**をコードで描く。
- **画像の指示に「文字・数字・ロゴなし」「縁なし・日付の刻印なし」を入れる。** 写真風にすると白い縁・角丸・「SUMMER 1997」・勝手な日付が入りやすい。日付はコードで描く（オレンジの7セグ数字）。
- **時代の小物は場面ごとに指示する。** 全カット共通で「ブラウン管テレビ」と書くと、バス停や屋台にまでテレビが出る。
- **TTS の演技指示は英語の構造化プロンプトで。** 日本語で指示を書くと指示文まで読み上げる。語尾が変わることがあるので文字起こしで確かめる。
- **同じ人物は同じ声。** 声を変えるなら、その人物のセリフを全部替える。
- **事実と数字には出典。** 発売年・ブームの年・旋律の作曲者の没年を確かめてから使う。歌詞は保護期間を確かめ、切れていなければ使わない（references/rights.md）。
- **AI で作ったと分かるように。** 概要欄に「実在の記録ではなく、AIで作った再現・フィクション」と書く。実在の人物・店・学校に似せない。
- **落ち着いて見られる音に。** 急な大音量を作らない（雷・花火は遠く、チャイムは控えめ）。遠くからの呼び声では周りの音を下げない。
- **費用の大きい生成（Veo・大量の作り直し）は、見積もりを伝えて了承を得てから。**

## 4. 演出のコツ
- 1カット8〜9秒、クロスフェード1.6秒（章の変わり目は2.2〜2.6秒）。カメラは5〜9%のゆっくりしたズームかパン。
- 冒頭5秒以内に「写真が動き出す」を見せる（何が起きる動画かを一瞬で分からせる、いちばん効くフック）。章の入口でくり返すと章立てにもなる（全部で5回前後）。章の入口には小さな日英キャプション（「1997年8月　縁側」）。
- セリフは全体で4〜8行。説明しない。最後に視聴者への問いかけ（エンドカード・概要欄・固定コメント）。
- 「あるある」を細かく：電池を手でこすって温める、肉抜き、コースアウト、電子ペットが朝おばけになっている、5時のチャイム、8月31日の宿題、おばあちゃんのがま口、ブラウン管の野球中継と縁側の柴犬…。コメント欄で自分の思い出を書きたくなる。
- 単調さを避ける：物語（友情・初恋・別れ）と季節・天気の変化（夕立・虹・花火・赤とんぼ）。
- 環境音パートは人物なし・各30秒の長回し。場面ごとの音の大きさをそろえる（平準化が効く）。

## 6. 失敗したとき
- **402（前払いクレジットが尽きた）**：生成済みの素材で最後まで作る。BGM は synth_music.py、声は生成済みのものだけ、問題の画像は fixes.json のぼかし・切り取り（作り直せない人物違いは手元や背中だけ見える範囲に切る）、別カットの画像を差し込みに使う（`img`）。未達の項目と、補充後にやること（費用つき）を検証レポートに書く。
- **502 / 500**：一時的なことが多い。再試行（スクリプトは自動で再試行する）。検索つきは `--think low` が通りやすい。YouTube の5分以降の区間は 500 になる（読めない）。
- **処理が遅い**：長い畳み込みは使わない（移動平均は累積和で）。リバーブは区切って計算（sfx.py）。レンダリングは画像の事前縮小＋`resize(box=…)`、色調整とにじみは画像ごとに焼き込み済み。重い区間で1本だけ遅れたときの直し方は references/quality.md の 10.。
- **自分のシェルを止めてしまう**：`pkill -f "パターン"` はそのコマンド自身にも当たる（パターンの文字列がコマンド行に入るため）。プロセスは `ps` で PID を調べて `kill PID` で止める。
- **長い処理が途中で止められる**：バックグラウンド実行には時間の上限がある。最終結合（12分の1080pで約20分）などは十分長い上限で動かす。途中で止まった mp4 は「moov atom not found」で再生できないので、作り直す。
- **アプリで動画が送れない**：送れる大きさに上限がある（30MB 程度）。`finalize.py --small` で 28MB 以下に。
