## 1. 見積書の金額

元の Excel と同じく、どれも 1円未満を **切り捨て（ROUNDDOWN）**。
- 部材の単価 ＝ 定価×0.8（`estimateRate`）。見積の単価を手で入れた行は、その単価（備考の「×0.8」を付けない）。
- 金額 ＝ ROUNDDOWN(数量×単価)。割り切れない数量（1m÷3m など）は丸める前の数量で計算する。
- 小計 ＝ 部材＋施工費、諸経費 ＝ 小計×0.1（`estimateOverheadRate`。見積書ごとに手で直せる。欄を開いて変えずに確定（F2→Enter など）しても手入力にしない。自動と同じ値を打ったら手入力を外す＝null。2026-10-23）、消費税 ＝ (小計＋諸経費)×0.1、合計 ＝ 小計＋諸経費＋消費税。
  **諸経費は合計の末尾が0になるよう端数調整**（ユーザーの指示「諸経費は端数調整のために合計金額の末尾が0になるように」2026-10-22。`overheadAuto`）：小計×0.1 から1円ずつ（20円まで）下げる。
  例：小計 37,568 → 諸経費 3,751・消費税 4,131・合計 45,450。サンプルの答え（下）は 諸経費 2,220・合計 26,950 になる。Excel は 小計×0.1 と違う金額なら数字で書く（式にしない）。
- 備考（定価等）・算出根拠は「定価8,000円（税抜）×0.8」。
- サンプルの答え合わせ：玄関（木の手すり 定価20,000円 1本4m を 60cm → 0.15本×16,000＝2,400、同上施工費 木2箇所 3,000（見積の単価 1,500×2）、ブラケット 2,100×0.8＝1,680×2）、
  トイレ（L型 11,000×0.8＝8,800、同上施工費 タイル2箇所 4,000（2,000×2）、キャップ 450×0.8＝360×2）→ 小計 22,280・諸経費 2,228・消費税 2,450・合計 26,958。
- 見積もり作成日（`Job.estDate`）：見積書の右上の作成日。見積書に行をはじめて入れた日（それまでは作った日。`calc.ts` の `startEstimate`）。複製は当日、消したら当日（「施工日ではなく見積もり作成日。何も入れなければ当日」の指示、2026-10）。
  見積書の画面に施工日（`Job.date`）は出さない（請求書を確認するの様邸・仕切り計算表には残る）。前の版の見積書は、前に覚えた作成日か作った日。
- 月の3つ（2026-10-26）：**見積もり作成日**（上）と、**請求する月**（`Job.month`。工務店の請求書に入れる月・一覧の月）と、**売上月**（`Job.salesMonth`。売上見込み・受注残・進捗管理の月）。
  ユーザーの話「見積もり作成日と、請求月というか販売月というか工事が発生する月っていうのは大きく異なります。10月末に見積もり作った分は、でも11月に売り上げになる」
  「請求月と販売月は基本的には同じです。まれに違うことがあります」→ 売上月は請求する月とちがうときだけ持ち、ふだんは請求する月と一緒に動く（`salesPlan.ts` の `withSalesMonth`・`withBillMonth`・`shiftSalesMonth`）。
  特定福祉用具の案件の売上月は、初めは納品日（なければ承認日・申請日・見積日）の月（特定福祉用具の `salesMonthOf`）で、このアプリで変えた月は設定の `tokuteiSalesMonths`（受注残にもこの月で渡す）。
  様邸の「🏷 販売見積書」のタブの上の「売上月」でも選べる（「特定福祉用具に関しても、売上を10月にいれるのか、11月にするのかを選択できるようにする。仕入れの月は不要」2026-10-28）：
  工事見積書の売上月と同じく、案件の月とちがうときだけ持ち（薄い黄色）、同じ月に戻すと持たない（`withTokuteiSalesMonth`）。特定福祉用具には請求する月（仕入れの月）は作らない。
- 担当（`Job.staff`）：受注残・進捗管理にはこの名前で、受注残の担当者（行橋営業所は姓だけで登録＝「久保・土居・宮村で苗字は全く同じで同一人物です」）につないで入る。
  様邸の担当は特定福祉用具の案件の担当にもなる（⇔。特定福祉用具で選び直しても様邸に入る）。
- **介護保険の内訳**（明細の下。ユーザーの指示「工事見積書にも販売見積書と同様に記載する。記載する、記載しないは販売見積もりと同様に選択できるようにする」2026-10-28。`careLines.ts`）：
  介護保険の対象＝min(介護保険の対象の合計（税込）, 200,000)（`HOUSING_LIMIT`）、負担割合の分＝ceil(対象×割合÷10)、保険者負担（保険給付額）＝対象−負担割合の分。売上伝票（`uriage.ts`）と同じ計算で、
  委任状の保険給付額（`shinsei.ts` の `benefit`）にも使う（`careAmounts`）。サンプルの答え（1割）：対象 26,950・利用者負担 2,695・保険者負担 24,255。
  行は特定福祉用具の販売見積書（tokutei の `estimateBook.ts` の `insuranceLines`）と同じ言葉・順番。負担割合を選ぶまでは「介護保険（受領委任払い）」「介護保険の対象」だけ。
  利用者負担は赤字（#c00000・Excel は C00000）。生活保護は「生活保護（N割）」で赤字にしない（「介護扶助」と書かない）。償還払い（売上伝票の `billing: 'reimbursement'`）は「いったんお支払いいただく金額」と払い戻しの行。
  「自己負担額を表示」を外した様邸（`showSelfPay: false`）は書かない。

## 2. 切って使う部材（手すり・ベースプレート）

- 部材ごとに「1本の長さ」（`pieceLengthM`、m）を持つ。商品名の「4m」「4000mm」「L=4000」から自動で入る（`priceImport.ts` の `guessPieceLengthM`）。
  幅・厚み・径・高さの寸法（「120mm幅」「幅120mm」「W=120mm」「φ35mm」「35mm丸」「厚み15mm」「t12mm」「H=800mm」「出幅75mm」）と 20cm 未満は長さにしない。2つ以上なら L=・長さ の付いたもの、なければ長い方。
  前は最初の「○mm」を長さにしていて、マツ六 BH-412「木製ベースプレート 120mm幅 … 2m」を 0.12m と読んでいた（備考「定価○円（0.12m）」「144mm÷120mm＝1.2」。2026-10-22 の指摘）。
  前の版の読み方のまま保存してある部材・行は読み込むときに直す（`storage.ts` の `oldPieceLengthM`・`pieceLength`・`rowLength`。行は本数を変えないよう使う長さも直す）。
- **申請書の寸法 ⇔ 見積書の本数**（「どちらか一方を入力した際に、自動的に 1.2 の部分が入力される」2026-10-22。`cutLink.ts`）：申請書の長さ（L=600×1800）→ その箇所の手すり・ベースプレートの使う長さ（2400mm＝1.2本）。「600×2」「600mm×2本」は 600mm が2本（`dimsLengths`。前は 602mm と読んでいた）。見積書で内容を選び直すと、前の部材の切った長さは残さない（2026-10-23）。
  見積書で手すりかベースプレートの数量を入れる → もう一方も同じ長さ（前から同じだったか空のとき）。申請書の長さが前は見積書と同じだったなら空けて見積書の長さを出す。
  長さの分かっている箇所に部材リストから入れた手すり・ベースプレートはその長さ（`fillAdded`）。長さで数える行＝1本の長さがあり、使う長さがあるか 1.5m 以上の材で1本以下（`cutRow`）。
- **中間のブラケット**（「見積書で、中間のブラケット（BD-01G）の数も」→「おねがいします」2026-10-22。`cutLink.ts` の `withBrackets`・`midBrackets`）：
  マツ六 BAUHAUS の 35 の丸棒（品番 BD-1［色］［長さ］）はブラケットの間 900mm 以内（メーカーの決まり。32 の丸棒は 700mm だが今は数えない）。
  両端＝35エンドブラケット（BD-08G。手で入れる）、中間＝35ブラケット横型（BD-01G）を手すり1本に ceil(長さ÷900mm)−1 個。手すり1本は申請書の長さの区切り
  （区切りの合計が見積書の手すりの長さと同じとき。L=600×1800 は 0＋1＝1個）、なければ見積書の手すりの行（使う長さ×本数、切らない材は 1本の長さ×本数）。
  手すりの長さが変わったとき（申請書の長さ・見積書の数量と備考・部材リストと常用から入れた）だけ入れ直す。前の長さの数・0・前は長さが分からない・いま入れた行なら新しい数、
  手で別の数・2行に分けてあればそのまま。行がなければ手すりのすぐ下（同上施工費があればその下）に部材リストから（色は端のブラケットに合わせる。なければ品番だけの行）。
  900mm までにしたら、入れたままの行（単価・内容・備考を直していない）は外す。見積書の行なので、仕切り計算表・発注書・販売受注簿にも同じ数が出る。
- 数量の欄に「60cm」「600mm」か小数（0.15）を入れると、数量 ＝ 使う長さ÷1本の長さ（例：600mm÷4000mm＝0.15本）。整数なら本数（規格品をそのまま使う）。
- 見積書の数量は「本」、備考は「定価20,000円（4m）×0.8」、2行目に「600mm÷4000mm＝0.15」（同じ長さを2本なら「600mm÷4000mm×2＝0.3」）。mm を付けるのはユーザーの指定。
- 笹岡工務店の仕切り計算表も同じ本数（仕切価格×0.15）。
- 単位のない既製品の手すり（TOTO インテリア・バーなど。部品は除く）は「本」と出す（`estimateForms.ts` の `rowUnit`）。

## 3. 施工費と「同上施工費」

- 施工費は笹岡工務店の取付手間（木・タイルなど、1箇所あたりの単価。マスタの「施工費（笹岡工務店の手間）」）を数えて入れる。
- **取付手間は 仕切り（笹岡工務店からの請求）と見積（見積書に入れる単価）の2つの単価を持つ**（`LaborItem.price`・`estPrice`。行にも `Row.estPrice` で写す）。
  「笹岡からの仕切りなので、見積の金額はこちらから指示する。マスタで仕切りと見積の両方を入れられるように」「デフォルトは右に入れている金額」の指示（2026-10）。
  見積の初期値はユーザーの表（16項目：木 1,500・補強板 2,500・補強板2-3m 4,000・基礎工事 9,000・レバーハンドル 2,500・ウォシュレット部品代 3,000・タイル 2,000・
  踏み台タイル 4,000・スタンド 4,000・敷居撤去 15,000・安寿框手すり 3,000・エルボ 1,500・補強板3m以上 5,000・コア抜き 6,000・矢崎ステップ台 4,000・ウォシュレット 10,000）。
  表になかった「踏台 木」は「踏み台は取り付け1箇所2000円で計算」の指示で 2,000円（見積が空欄の項目は 仕切り×`estimateLaborRate`（1.5））。同じ表をもう一度もらったときは、変わっていないことを確かめて伝えた。
  前の版で保存したマスタ・見積書の行の空欄は、読み込んだときに一度だけ直す（設定の `laborRev` が `LABOR_REV` より古いとき。App.tsx。手で入れた単価は変えない）。見積の単価の初期値を変えたら、ここに足して `LABOR_REV` を上げる。
  前の版の見積書の施工費の行には、読み込んだときに一度だけマスタの見積の単価を入れる（設定の `laborEst`）。見積書で打った施工費は見積書だけの値（`estAmount`）。
  広域連合用の 時間 は 見積の金額÷2,500円（木 2箇所＝3,000円 → 1.2時間）。
- 部材のすぐ下に続く手間の行は、見積書では「同上施工費」1行にまとまる（金額は手間の合計）。箇所の最初にある手間は「施工費」。
  続けて並んだ手間はいつも1行になるので、別の行にしたいときは間に部材が要る（貼り付けた施工費が上の施工費にまとまるのはこのため）。
- 見積書で施工費の金額を直したとき、数えた手間の行は残して、差を「施工費（調整）」の行で足し引きする（仕切り計算表の取付手間も同じ金額になる）。
- 苅田町・行橋市・みやこ町用は「1式」。広域連合用は「時間×1時間の単価（2,500円、`estimateHourRate`）」で書き、割り切れない金額は1式。
- 「部材＋施工費（常用）」（型 `Kit`）＝よく使う部材と施工費のセット。マスタの3つ目のタブで登録し、見積書のツールバーから入れる。
  例のセット「（例）手すり BD-134＋金具 BD-08G＋施工費」を最初に1つ入れる（ユーザーの例。BD-134 の本数は見積ごとに違うので空け、施工費は木 2箇所＝見積 3,000円。`samples.ts` の `exampleKit`、1回だけ＝`kitExample`）。
  数量 0 の部材の行は見積書・印刷・Excel で数量・金額を空欄にする（あとで本数を書く）。
- 見積書のツールバーから入れる部材・施工費・部材＋施工費（常用）は、**見積書で選んでいる（タップしている）行**に入れる（ユーザーの指示「タップしている部分に施工費や部材をいれる」、2026-10）。
  部材・常用はその行（と同上施工費）のすぐ下、空白の行ならその行に。続けて選んだ部材はいま入れた行の下。行を選んでいなければ箇所のいちばん下。
  施工費はその部材の同上施工費（同上施工費を選んでいればそのまとまり）。空白の行ならその行に入り、すぐ上の部材の同上施工費になる（箇所のはじめなら施工費）。
- 挿入した空白の行に施工費の言葉（「同上施工費」など）を打つと施工費の行にする（前は部材の行になり、仕切りの取付手間に入らなかった）。
  広域連合用でいちばん下の行を「手」にして時間を打つと、その行の単価の金額（上のまとまりが手入力ならそこに足す。前は上の同上施工費が打った金額に置きかわった）。
- 部材を選ぶ画面の − で部材が 0（行を消す）になったとき、すぐ下の施工費は、すぐ上も施工費の行なら一緒に消す（見積書の ✕ と同じ。残すと上の施工費のまとまりに入り、
  見積書と仕切り計算表が合わなくなった）。上が部材なら、その部材の同上施工費として残す（`rows.ts`。どれも 2026-10-23）。

## 4. 保険者と見積書の書式

申請書は保険者ごとに違うので、見積書ごとに保険者（`Job.insurer`）を持つ（2026-10 の指示で、作るときに4つから選ぶ形にした）。

| 保険者 | insurer | 見積書の書式 |
|---|---|---|
| 苅田町 | kanda | 苅田町・行橋市・みやこ町用「工事費見積書兼工事費内訳書」（1ページ18行） |
| 行橋市 | yukuhashi | 同上（3つとも同じ見積書） |
| みやこ町 | miyako | 同上 |
| 広域連合（福岡県介護保険広域連合：築上町・豊前市・上毛町・吉富町） | kouiki | 広域連合用「住宅改修内訳明細書」（1ページ14行、Ｐ－1・Ｐ－2） |
| 福岡市（2026-10-29） | fukuoka | 苅田町・行橋市・みやこ町と同じ（市の様式は「見積書（工事費内訳書）」で書式の決まりがない） |
| 北九州市（2026-10-29） | kitakyushu | 苅田町・行橋市・みやこ町と同じ（市の「①工事費見積書」と同じ表。市の記入例にも「上記の見積書の内容が記載されていれば任意のものでも可」） |

- 書式は保険者で決まる（`estimateForms.ts` の `jobForm`）。保険者を選ぶ前の見積書は、住所の市町村（書式と食い違わないとき）か、広域連合用なら広域連合。分からなければ空（画面で選ぶ）。
- 工事場所の住所の市町村が保険者と違うときは、知らせて「保険者を○○にする」ボタンで変える。打っている途中で勝手に変えない。申請書のタブでも同じく知らせる（2026-10-23）。
- **見積書の文字は欄からはみ出させない**（「文字のはみ出し…横が切れていたり…見積もりの枠からはみ出ていたり…しっかり見て」2026-10-22。`print/fit.ts`）：
  字の幅は半角の英数字・記号を字ごとに数える（数字 0.63・W や M は約 0.93 字分。前は半角をみな 0.55 で数えて品番が 1〜2px はみ出した）。長い商品名は言葉の切れ目で2行（広域連合用は3行まで。`wordLines`）。
  小さくして入れ、4.5pt より小さくなる長い文字（長い手入力の備考など）は欄の中で折り返して、欄に入るいちばん大きい字にする。改行と大きさは fit.ts で決め、画面・印刷・Excel で同じ（Excel の縮小に任せない）。
- 苅田町・行橋市・みやこ町用は、お客様名・介護保険被保険者番号・工事場所・作成日（令和）を見積書の欄に打つ。広域連合用はお客様名・工事場所を見積書の上の欄に打つ。
- 施工業者名・代表者（所長）・担当と電話は設定（営業所）から。ポータルで選んだ営業所（localStorage の `taiyo_portal_session`）を最初の設定に使う。

## 5. 改修場所・改修の種類・写真番号

- 箇所（`Place`）＝改修場所。名前は設定の「箇所の名前」（`placePresets`）から選ぶか、手で打つ。候補は苅田町の写真の用紙の改修箇所の□と同じ名前・順番
  （廊下・階段・台所・居間・食堂・寝室・洗面・脱衣室・浴室・トイレ・玄関・玄関～道路。その他は「＋ そのほか」で名前を打つ）。ユーザーの指示「箇所を足すの項目は、写真の用紙の□玄関などの項目にあわせる」（2026-10-21）。
  前の初期値（玄関・上がり框・…・屋外・アプローチ）のまま保存してある設定は、読み込んだときに新しい候補にする（設定の版5。自分で直した候補はそのまま）。
  見積書の欄では「▼」か Alt+↓ で候補が出る。「①勝手口」「浴室③」のように写真番号を付けて打てる。

## 9. 発注書（何を何本・何個発注するか）

2026-10 の指示：「見積もりに入っている個数の部材を、何が何個・何本か分かるように発注する。手すりは 4000mm なら、0.15本が2本・0.4本が1本なら 2000mm を1本。
合計が0.1未満は危ないのでもう1本。ベースプレートも枚数で同じ。マツ六（BD-134・BD-132）のこと。その他は見積もり通り。増減・削除もできる」。
実装（`order.ts`）：
- 同じ部材（メーカー・品番・品名が同じ）は箇所をまたいで足す。施工費・空白の行・金額だけの行は入れない。規格品は見積書の数量のまま。
  同じ品（メーカー＋品番＋品名・単位・1本の長さ）の行は1行にまとめる（2000mm の行も。BD-132 をそのまま使う箇所と BD-134 を切った残りを 2000mm にした箇所があると、2行に分かれていた）。
- 切って使う部材（1本の長さと使う長さがある行）は、使う長さを足して1本の長さ（4000mm）の本数にする：
  1. 長いものから順に、入る1本に入れていく（1本より長いものは継ぐ：まるごとの1本＋残り）。
  2. いちばん少ししか使わない1本が半分（2000mm）で足り、それでも余りが 0.1本（400mm）以上なら 2000mm にする。
  3. 余り（発注する長さ−使う長さ）が 0.1本より少なければ、もう1本（2000mm が使えれば 2000mm）。
  - 例：600mm×2＋1600mm＝2800mm（0.7本）→ 4000mm 1本（余り1200mm）。1600mm（0.4本）→ 2000mm 1本（余り400mm）。3800mm（0.95本）→ 4000mm 1本＋2000mm 1本。
    2100mm×2 → 4000mm 2本（2000mm からは切れない）。ユーザーの例「0.15×2＋0.4 → 2000mm」は 2800mm で入らないので 4000mm にし、報告で説明した。
  - 申請書の長さを1行に足した手すり・ベースプレート（L=2100×2100 → 4200mm の1行）は、継いだ1本とみなさず区切りごとに1本ずつ数える
    （区切りの合計が行の長さと1mm以内で同じとき。中間のブラケットの `railRuns` と同じ判定。前は 4000mm 1本＋2000mm 1本にしていた。2026-10-23）。
- 2000mm の品は部材リストから探す：同じメーカー・1本の長さが半分・長さを除いた品名が同じ。品番の見当（BD-134→BD-132、HD5-4000→HD5-2000）は手がかりだけ。
  見つからず1本が 4000mm なら、品番・価格を空けた「2000mm」の行に「品番・価格を確かめてください」と出す（間違った品番を発注書に書かないため）。
- 数は ＋／− で直し、✕ で消し（戻せる）、部材リストから足せる（見積書にある部材ならその行の数が増える）。直したところは `Job.order`（数・消した行・足した行・発注先・発注日）に持ち、
  見積書を直しても残る。見積書から計算した数が変わった行には「見積書から計算した数は○本 戻す」。
- A4縦の発注書（数量と単位を大きく）。出すのは 発注先 御中・発注日・発注元（会社・営業所・住所・TEL/FAX・担当）・「下記のとおり発注いたします。」・件名（○○様邸 住宅改修の部材）と、
  No.・メーカー・品番・品名・数量・単位・写真番号の表だけ。No. は数が 0 の行に付けない（画面も印刷と同じ番号）。URL の `&view=order` で読み直しても発注書が開く。
- **どこで使うか（写真番号）を部材ごとに出す。** 「その部材をどこで使うかを写真番号で分かるように明記・紐付け」との指示（2026-10）。
  `OrderLine.photos` は見積書の写真番号（`estimateForms.ts` の `photoNumbers`：入れた写真番号、なければ見積書に出る順番）を、同じ部材をまとめた行ごとに小さい順で持つ。
  2000mm の行（足す分）も同じ番号。発注書で足した行は空。表示は丸数字（`photoLabel`：「①③」、21からは (21)）。印刷はいちばん右の「写真番号」の欄、画面は品番の横。
  販売受注簿には渡していない（頼まれていない）。
- **要らないものは出さない。** 「〇〇までに納品など、不要な部分が入っています」と言われ、備考の欄（例：○月○日までに納品）・品目数（6品目（4本・5個・1枚））・
  現場（お客様の住所）を印刷から外した（備考は画面の欄も `OrderEdits.note` もなくした。品目数は画面の見出しにだけ残す）。足すときは本当に要るかユーザーに確かめる。
- **計算の説明は出さない。** 前は品名の下に「使う長さ 3800mm×1本＝3800mm（0.95本）→ 4000mm 1本＋2000mm 1本（余りが…）」「S-TS35（4000mm）の余りが少ないので足す分」
  「玄関 3個＋トイレ 2個」を出していたが、印刷にスクリーンショットで丸を付けて「＋分などの説明は不要です」と言われ、画面・印刷・販売受注簿への転記（note）から消した
  （`OrderLine` に説明の項目はない）。発注書は「何を何本」だけ。2000mm の品がないときの「確かめてください」（`warn`）だけは画面に残す（印刷には出さない）。
