# YouTube の中身を読み取る

YouTube の URL を受け取ったら、軽い方法から順に試して「何が映り、何が聞こえ、どう作られているか」を集める。
見られなかった部分を推測で埋めない（「未確認」と書いて、読む方法を案内する）。

- `<SKILL>` はこの SKILL.md のフォルダ（`scripts/` がある所）
- スクリプトは Node 18 以上だけで動く（追加のパッケージ不要）。クラウドの作業環境のプロキシにも自動で対応する
- 詳しい準備・コマンド・エラーの直し方は `references/methods.md`

## 0. 環境を確かめる（最初に 1 回）

```
node <SKILL>/scripts/yt-read.mjs --check <URL>
```

YouTube・サムネイル用のドメイン・Gemini（動画の最初の 1 秒だけで試す）・yt-dlp・JS ランタイム・ffmpeg を ✓／✗ で出す。✗ のときは：

- **YouTube に届かない（クラウドの作業環境）**：ユーザーに環境のネットワーク設定を変えてもらう。画面上部のクラウド環境メニュー → 環境の編集 → Network access を Custom → Allowed domains に `youtube.com` `*.youtube.com` `youtu.be` `*.ytimg.com` `*.googlevideo.com` `youtubei.googleapis.com` を 1 行ずつ（既定のリストを含めるチェックは入れたまま）。約 1 分で今のセッションにも反映される。**第三者のミラー・ダウンロードサイト・別のプロキシで迂回しない**
- **Gemini が 402**：クレジット切れ。ユーザーに AI Studio（https://aistudio.google.com）でチャージしてもらう。401／403 はキーの問題。キーはユーザー自身に `.env` へ書いてもらい、チャットに貼らせない・表示しない
- **yt-dlp・ffmpeg が無い**：`references/methods.md` の 2 章の入れ方を案内する（クラウドなら自分で `pip install -U "yt-dlp[default]"`）

待っている間も、届く方法で進められるところは進める。

## 1. 目的に合う方法を選ぶ

| 知りたいこと | 方法（上から順に試す） | 要るもの |
|---|---|---|
| タイトル・投稿者・概要欄・長さ・タグ・公開日・チャプター | `yt-read.mjs` | youtube.com |
| サムネイル・場面の流れ（数秒おきの縮小コマ） | `yt-read.mjs`（ストーリーボード） | *.ytimg.com |
| 声の中身（字幕・文字起こし） | ① `yt-read.mjs` の字幕 → ② `yt-frames.mjs --subs`（yt-dlp）→ ③ `yt-gemini.mjs --mode transcript` → ④ `--audio` の音声を文字起こし | 方法ごと |
| 画作り・カット割り・音量・無音（実測の数字） | `yt-frames.mjs`（低画質を一時取得してコマ抜き。終わったら消す） | yt-dlp＋JS ランタイム＋ffmpeg |
| 映像と音をまとめて理解（語り口・BGM・雰囲気） | `yt-gemini.mjs` | Gemini（公開動画のみ） |
| どれも使えない | ユーザーに頼む（4 章） | — |

ブラウザの道具（Claude in Chrome・内蔵ブラウザ）が使えるときは、ページの概要欄と「文字起こしを表示」のパネルを読み、要所でスクリーンショットを撮る方法もある（`references/methods.md` 7 章）。

## 2. 基本の流れ

1. `node <SKILL>/scripts/yt-read.mjs <URL> --out <作業フォルダ>/yt_<動画ID>` を実行し、`info.md` を読む。`thumbnail.jpg` と `storyboard/` のシート（時間帯は `storyboard/index.md`）を Read で見る
2. 声の中身が要るのに `transcript.txt` が無ければ、表の順で取る
3. 作り方まで要るなら 3 章（制作分析）
4. 報告する：わかったこと、どの方法で読んだか、読めなかったもの（理由と次の手）

### スクリプト

| スクリプト | 何をするか | 主なオプション |
|---|---|---|
| `yt-read.mjs <URL>` | oEmbed・視聴ページ・字幕・サムネイル・ストーリーボード。動画はダウンロードしない | `--out` `--lang ja,en` `--tlang ja`（字幕を日本語に自動翻訳）`--sb-max 40` `--no-storyboard` |
| `yt-frames.mjs <URL｜動画ファイル>` | 時刻入りのコマのシート、カットの切り替わりと 1 カットの長さ、ラウドネス（LUFS）、無音の割合、文字起こし用の音声 | `--every 5` `--grid 4x4` `--scene 0.3` `--audio` `--subs` `--start 1:00 --end 3:00` `--keep` |
| `yt-gemini.mjs <URL>` | Gemini が映像と音声を見て答える（少しずつ受け取るストリーミングが既定。長い分析でも途中で切れにくい） | `--mode summary｜transcript｜scenes｜breakdown｜ask` `--q "質問"` `--out` `--start/--end` `--res low｜medium｜high` `--fps` `--model` `--no-stream` |

- `yt-gemini.mjs` の `--out` に `yt-read.mjs` の出力フォルダを渡すと、タイトル・概要欄・チャプターを前提情報として添える。結果は `gemini-<mode>.md`
- Gemini の費用の目安は、低解像度（既定）で 1 秒あたり約 100 トークン（10 分で約 6 万、27 分で約 15 万）。1 回の分析ごとに動画全体を読むので、同じ動画に何度も聞くと費用が重なる。聞きたいことは 1 回にまとめ、細部は `--start/--end` で区間を絞る
- 要約（summary）と分解（breakdown）で答えが食い違うことがある（例：BGM の有無）。食い違いは「要確認」として残し、区間を絞った ask か、yt-frames の実測で決める
- Gemini に渡す指示文は `references/prompts/` にある（目的に合わせて直してよい）

## 3. 制作分析（同じような動画を作りたいとき）

「この動画みたいなのを作りたい」「作り方を真似したい」と言われたら、内容ではなく**作り方（型・技法・数値）**を抜き出す。書式は `references/breakdown.md`。

1. `yt-read.mjs`：概要欄・タグ・チャプター・ストーリーボード
2. `yt-frames.mjs`：カットの長さ・つなぎ・質感・音量・無音を実測（使えなければストーリーボードから目測し「目測」と書く）
3. `yt-gemini.mjs --mode breakdown`：声・音楽・語り口・全体の型（使えなければ字幕とコマから推定し「推定」と書く）
4. 3 つを突き合わせて `breakdown.md` を作業フォルダに書く。測った値と Gemini の目安がずれたら、測った値を採る
5. 最後に「スタイルカード（守る核・数値・避けること・毎回変えるもの）」と「借りてよいもの／借りないもの」を必ず書く

制作用のスキル（ai-video-studio・motion-vault・チャンネル専用の制作スキルなど）があれば、breakdown.md を渡してそちらで作る。

## 4. どの方法も使えないとき

- ユーザーに頼む：タイトルと概要欄のコピー、YouTube の「…」→「文字起こしを表示」の全文、要所のスクリーンショット 5〜10 枚、動画ファイル（本人が持っている場合だけ）
- 動画ファイルがあれば `yt-frames.mjs <ファイル>` で同じ分析ができる
- 分からない項目は「未確認」と書いて残し、作り話で埋めない

## 5. 守ること

- **迂回しない**：ネットワーク制限・ボット確認・年齢制限・非公開を、第三者のサイトや他人のアカウント・Cookie で回避しない。設定の変更をユーザーに頼む
- **取得した動画・音声は分析のためだけ**：低画質で取り、分析が終わったら消す（`yt-frames.mjs` は既定で消す）。新しい動画の素材（映像・音楽・声・台詞・サムネイル）に使わない
- 字幕・文字起こしの全文や歌詞を、公開する動画や文章にそのまま使わない（分析メモの中だけ）
- 非公開・限定公開・メンバー限定は、読める範囲だけ（Gemini の URL 読み取りは公開動画のみ）
- API キーを表示・出力・コミットしない。チャンネルへの操作（高評価・コメント・登録）はしない
