# 特定福祉用具 購入申請書・見積もり作成（太陽シルバーサービス 行橋営業所）

介護保険の特定福祉用具の販売で、仕切り一覧表から商品マスタを作り、★お気に入りから選ぶだけで、定価の2割引きの見積書（介護保険の内訳つき）を作るアプリ。
使うのは行橋営業所の福祉用具専門相談員（プログラマーではない）。スマホとパソコンで使い、スクリーンショットに丸を付けて頼んでくる。
このスキルは 2026年10月のセッション（見積書を Excel で保存できるようにした）までの知識をまとめたもの。

ポータル全体に共通のこと（公開の流れ・ユーザーの好み・報告のしかた）は `taiyo-portal` スキル、Excel の作り方の詳しいことは `taiyo-excel-export` スキルにある（入っていれば一緒に読む）。

## 計算の決まり（`calc.ts` の1か所だけで計算する）

金額は印刷・Excel・これから作る申請書・受注簿で同じでなければならないので、`saleTotals(sale, settings)` 以外で計算しない。
- 販売単価：定価×(100−割引率)%（割引率は設定の 20 → 定価×0.8）、1円未満切り捨て。品目の単価を手で入れたら（`unitPrice`）それを使う。定価がない商品は 仕切×1.25（`markupRate`）。
- 消費税は行ごとに切り捨て。非課税の品目は消費税の欄が「非課税」。
- 介護保険の対象＝購入金額と「今年度の残り」の小さい方。**残りが空欄なら限度額 10万円**として計算する（ユーザーの指示）。**0 は「もう残っていない」**で、空欄とは別。超えた分は全額ご負担。
- 利用者負担＝対象×負担割合（1〜3割）を**切り上げ**、保険者負担＝対象−利用者負担。整数で計算するので 3割でも1円もずれない。
- 個別切り上げ（品目ごとに切り上げ）：みやこ町は最初からオン（要確認）。超えた分がなく、金額のある品目が2つ以上のときだけ効く。
- 生活保護：利用者のお支払いは 0、負担割合の分は「介護扶助」。償還払い：「お支払いいただく金額（いったん全額）」と「あとで保険者から払い戻される金額」。
- 利益率が 20% 未満なら知らせる（`minProfitRate`）。
- 計算の例（テストで確かめている）：35,000円と13,800円の2品・1割 → 合計 42,944円、利用者 4,295円、保険者 38,649円。

## Excel で保存（`print/estimateXlsx.ts`・`print/xlsxBook.ts`）

- 印刷と同じ位置に枠を置いてセルを結合して作る（横は mm、縦は pt。列の境目は 2mm、行の境目は 0.3pt より近いとまとめる）。
- 金額・消費税・小計・合計・介護保険の内訳は Excel の計算式（`INT(ROUND(…))`・`CEILING`・`MIN`・`SUMPRODUCT`）。開いた時点の値（式の答え）も入れておき、印刷と同じになることをテストで比べる。
  残り・負担割合・生活保護・支払方法は、保存した時点の値で式に固定。
- 書体は BIZ UDP明朝 Medium と BIZ UDPゴシック。題名の字の間は空白でまねる（「御　 見　 積　 書」）。A4縦1枚に収める印刷設定。
- 直したら単体テスト（`test/tokutei/estimateXlsx.test.ts`）と、LibreOffice での計算し直し・画像にして印刷と見比べる（`taiyo-excel-export` スキルの確かめ方）。

## 落とし穴

- **作業ツリーを取り違えない。** 住宅改修（`claude/sasaoka-shikiri-app`）と同じリポジトリ。コミット・push の前に `git branch --show-current` を見る。
  リポジトリの名前が「-」なので、`cd -` は「前のフォルダに戻る」になってしまう。必ず `/home/user/-` と書く。
  リポジトリの `.github/workflows/deploy.yml` は main の健康管理アプリ用で、このアプリとは関係ない（このアプリはポータルに置いて公開）。
- **印刷は A4縦1枚に固定**（`tokutei.css` の `@media print` で `.est{height:296mm; overflow:hidden}`）。入りきらないときは中身（`.est-body`）を縮めて1枚に収める
  （ユーザーの答え「縮めます」2026-10-22。`EstimateDoc.tsx` の `useFitToPage`：縮める前の高さを A4 の幅との比で mm にして、置ける 266mm に入る割合で `transform: scale`、上を合わせて左右の中央。
  印刷の直前 `beforeprint` にも測る。印刷イメージの画面も A4 1枚に見せる `.est-shrunk`）。測ると**ふつうの2品の見積書でも中身が 291mm あり、前は備考が約10mm切れていた**（いまは 0.91 倍）。
  Excel も「1ページに収める」なので同じ見え方。e2e の `assertFits` で、画面と印刷の両方で備考の下が A4 の下の余白より上にあることを確かめる。
- テストで Excel の式を読むとき：XML の `&amp;` `&quot;` `&gt;` を戻してから比べる（文字をつなぐ式 `"合計（税込）　¥"&TEXT(…)` が合わなかった）。
  正規表現は式全体に合わせる（`^CEILING\(MIN\(` が利用者負担と「お支払い」の2つの式に当たった → `^CEILING\(MIN\([A-Z]+\d+,100000\)\*1\/10,1\)$`）。
- `print/xlsxBook.ts` の `esc` の正規表現に U+FFFE・U+FFFF が文字そのもので入っている（動くが、直すなら `\uFFFE\uFFFF` とエスケープで書く）。
- `.ts` のテスト（`node --test`）は TypeScript をそのまま動かすので Node 22.18 以上が要る。
- 一時的な検証用の .ts から `fflate` が見つからないときは絶対パス（`<作業ツリー>/node_modules/fflate/esm/index.mjs`）。esbuild でまとめるときは CJS（ESM だと「Dynamic require of util」）、`--node-paths` はないので環境変数 `NODE_PATH`。
- ヘッドレスの Chromium は日本語のダウンロード名が「download」になる → `LANG`/`LC_ALL` を `C.UTF-8`（e2e.mjs はそうしている）。
- ポータルへの push は作業環境の安全確認（本番への公開）で止められることがある。回り道をせず、ユーザーに「公開して」と言ってもらってから（`taiyo-portal` スキル）。
