# 特定福祉用具 購入申請書・見積もり作成（太陽シルバーサービス 行橋営業所）

介護保険の特定福祉用具の販売で、仕切り一覧表から商品マスタを作り、★お気に入りから選ぶだけで、定価の2割引きの見積書（介護保険の内訳つき）を作るアプリ。
使うのは行橋営業所の福祉用具専門相談員（プログラマーではない）。スマホとパソコンで使い、スクリーンショットに丸を付けて頼んでくる。
このスキルは 2026年10月のセッション（見積書を Excel で保存できるようにした）までの知識をまとめたもの。

ポータル全体に共通のこと（公開の流れ・ユーザーの好み・報告のしかた）は `taiyo-portal` スキル、Excel の作り方の詳しいことは `taiyo-excel-export` スキルにある（入っていれば一緒に読む）。

## 計算の決まり（`calc.ts` の1か所だけで計算する）

金額は印刷・Excel・これから作る申請書・受注簿で同じでなければならないので、`saleTotals(sale, settings)` 以外で計算しない。
- 販売単価：定価×(100−割引率)%（割引率は設定の 20 → 定価×0.8）、1円未満切り捨て。品目の単価を手で入れたら（`unitPrice`）それを使う。定価がない商品は 仕切×1.25（`markupRate`）。
- 消費税は行ごとに切り捨て。非課税の品目は消費税の欄が「非課税」。
- 介護保険の対象＝購入金額と「今年度の残り」の小さい方。**残りが空欄なら限度額 10万円**として計算する（ユーザーの指示）。**0 は「もう残っていない」**で、空欄とは別。超えた分は全額ご負担。
- 利用者負担＝対象×負担割合（1〜3割）を**切り上げ**、保険者負担＝対象−利用者負担。整数で計算するので 3割でも1円もずれない。
- 個別切り上げ（品目ごとに切り上げ）：みやこ町は最初からオン（要確認）。超えた分がなく、金額のある品目が2つ以上のときだけ効く。
- 生活保護：利用者のお支払いは 0、負担割合の分は「介護扶助」。償還払い：「お支払いいただく金額（いったん全額）」と「あとで保険者から払い戻される金額」。
- 利益率が 20% 未満なら知らせる（`minProfitRate`）。
- 計算の例（テストで確かめている）：35,000円と13,800円の2品・1割 → 合計 42,944円、利用者 4,295円、保険者 38,649円。

## 販売見積書（会社の見積書の原本に書く。`estimateBook.ts`・`print/estimateFiles.ts`・`print/mitsumori.xltx`）

- ユーザーの指示「見積書の原本はこのような形にする。プレビューを見ながら入力できるようにする」（2026-10-23。TSS の見積書の .xltx をいただいた）。
  前の、アプリで作った見積書（`EstimateDoc.tsx`・`estimateXlsx.ts`）はやめた（`print/xlsxBook.ts` は `taiyo-excel-export` スキルの見本として残す。アプリでは使っていない）。
- 原本：シート「見積書」（印刷範囲 A1:J62・A4縦・84%）とマスタ（営業所の住所・所長。H9 の営業所名から VLOOKUP）。**所長の印影の画像（図 3・図 5）は消した**
  （アプリは誰でも開けるページなので。印の枠の四角は残す）。保存した場所・作った人・コメントを書いた人（パソコンの名前）も消した。
- 書く欄：宛名 A6（「山田 花子　様」）・見積番号 I4（「№　…」）・見積日 I5（Excel の日付の数。書式は原本の 31＝和暦ではなく「2026年10月25日」）・営業所 H9・会社 H8・件名 B14（「特定福祉用具の購入」）・
  明細 23〜42行（品名 A＝商品名＋品番・数量 F・単位 G・単価（税抜）H・金額 I＝`IF(Fn*Hn,Fn*Hn,"")`（原本は26行目まで。下の行にも同じ式）・税率 J＝0.1／「軽減税率8%」／「非課税」）・
  備考 60〜62行（59行目は見出しの「備　　考」）＝介護保険の内訳・お支払いいただく金額・見積書の備考に足す文。入らない行・明細は画面で赤く知らせる。
- 合計（C46〜C51・E46〜E49・E21）は原本の式のまま、答え（`<v>`）もアプリと同じ計算で入れる（プレビュー・スマホのため）。`calcChain` は消す。
- 原本の明細の品名の欄は、2行目が 10pt・3行目が赤の太字 14pt（書いた例の名残り）→ 24〜41行を 23行目の書式にそろえる（42行目は下の罫線がちがうのでそのまま）。値段のない品目は単価を空に。
- プレビューは申請書と同じ `shinseiPreview.ts` の `sheetPreview`（型は欄の名前 `EstimateField` で汎用）と `ShinseiPages`。
  グループの図形（印の枠）も描き、印刷しない図形（`fPrintsWithSheet="0"`。原本の赤い枠・説明）は描かない。印刷の画面（`PrintView.tsx`）も同じ絵を、紙の余白（上14・下8・左17・右10mm）の中に収まる大きさで描く。
- 直したら `test/tokutei/estimateBook.test.ts` と e2e（`.est-sheet` の文字・Excel の E21／A60・PDF 1枚、23点で2ページ）、`taiyo-excel-export` の validate.py・recalc.py（空の金額の欄の「None と ''」の違いは問題ない）、LibreOffice で PDF にして見比べる（マスタのシートも印刷される）。

## 落とし穴

- **作業ツリーを取り違えない。** 住宅改修（`claude/sasaoka-shikiri-app`）と同じリポジトリ。コミット・push の前に `git branch --show-current` を見る。
  リポジトリの名前が「-」なので、`cd -` は「前のフォルダに戻る」になってしまう。必ず `/home/user/-` と書く。
  リポジトリの `.github/workflows/deploy.yml` は main の健康管理アプリ用で、このアプリとは関係ない（このアプリはポータルに置いて公開）。
- **見積書は3ページまで**（ユーザーの指示「ページは3ページまでいけるようにする」2026-10-25。`estimateBook.ts` の `contBlock`・`estimatePages`）：
  1ページ目は原本のまま（1〜62行・明細16行＝23〜38行）。17点目からは原本の下（63行目から）に「明細のつづき」を足す：1〜7行目の写し（題名・見積番号・見積日・宛名）＋22行目の写し（見出し）＋明細 `CONT_ROWS`＝42行
  （1ページ目の高さに入るだけ。**原本の39〜42行・53〜57行は隠した行**なので高さに入れない。テストが高さから数えて確かめる）。左上に「1／3」「2／3（明細のつづき）」。3ページで 100点（`ESTIMATE_CAPACITY`）。
  合計の式（C47〜C51 の SUMIF）に2・3ページ目の範囲を足す。印刷は手動の改ページ（62行のあと・2ページ目の終わり）にして、`fitToPage` を 0、`scale` を1ページ目が1枚に入る倍率（`fitScale`＝81。
  Excel は「1ページに収める」だと手動の改ページを使わない）。印刷の範囲（A1:K62）・dimension・税率の入力の規則（J 列）も広げる。1ページ（16点まで）は原本のまま（1ページに収める）。
  LibreOffice で PDF にすると、代わりの字体で列が広くなり K 列（備考）だけ別の紙に出る（Excel は数字の幅 8px で入る。3% ほど余る）。
- **原本の直し（2026-10-25）は `docs/tokutei/edit-mitsumori-template.py` で1回だけ**（直すときはスクリプトを直し、`git show <前のコミット>:src/tokutei/print/mitsumori.xltx` から作り直す）：
  灰色の地 → 薄い水色 `#DDEEF9`（ユーザーの指示「グレー系で暗いので、薄い水色系にする」）・列の幅・K列「備考」（算出根拠。ユーザーの指示「税率の横に、備考を入れて、算出根拠をいれる」）・
  会社の欄を左寄せ1行ずつ（会社名・営業所と所長・〒・住所・TEL・FAX・登録番号・担当。2026-10-26 から所長印・担当印の上の I8〜I16、行ごとに I:K の結合・縮小、会社名 14pt・営業所 12pt・ほか 11pt。
