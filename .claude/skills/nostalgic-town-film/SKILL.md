# 架空なのに懐かしい街の長尺映像

「存在しない街の記憶」系の作品（架空の街の一日を、説明なしの映像と生活音で見せる5〜10分の動画）を作る。
2026年10月に「AIと人間の共存 第一章」（昭和を残した2080年の海辺の町・継町、6分51秒・26カット）を作った手順と道具を、そのまま再利用できる形にまとめたもの。

## できあがるもの

- 1080p／30fps の動画2本：**テーマ曲入り**（-14 LUFS）と、元チャンネルの型に合わせた**環境音のみ**（-16 LUFS）。最後に短いあいさつの声
- スマホ確認用の軽量版（480p、各30MiB未満。会話の添付上限が30MiBのため）
- 高画質で見られる非公開の上映ページ（Artifact。音の切り替えと章の移動つき）
- 文書：参照動画の分析書、テーマ設定書（世界観・構成表・音の設計）、概要欄の文案

実例は `assets/examples/`（分析書・テーマ設定書・概要欄・画像と Veo の指示文）。迷ったらまずこれを読む。

## 最初にユーザーと決めること

聞かずに進めると、あとで高くつくものだけを確認する。それ以外は実例に合わせて決めてよい。

1. **参照動画の URL**（真似る「型」の元）と、**世界観**（時代・場所・技術・誰が暮らすか）
2. **尺**：「AIと人間の共存」シリーズは**7〜8分**（ユーザーの希望）。目安：1カット16秒（8秒の Veo を半速）、1.2秒ずつ重ねて 7分台なら 28〜31カット。長くなったら、説明のためのカットから外し、似た場面は一枚の絵にまとめる
3. **見た目**：写真風（実写に見える AI 画像）が基本。既存の原画（他の企画の採用画像など）があれば使う
4. **費用**：Veo 3.1 Lite の 1080p は 1秒 0.08ドル（8秒で 0.64ドル）。画像は1枚 約0.13ドル。26カットなら合計 約20〜25ドル（約3,000〜4,000円）。他の手段（Seedance など）を聞かれたら、この環境から使えるか（通信が通るか）も確かめて比べる
5. **追加の要素**（空中電子版、ひとりでに開く扉、ロボットの先生など）は、出るたびに構成表へ足す

## 準備

```bash
bash <このスキル>/scripts/new_project.sh <作業フォルダ> [slug]   # ひな形の複製、フォント導入、npm ci、道具の確認。slug は出力の名前
```

- フォント（Zen Old Mincho／Zen Maru Gothic、SIL OFL 1.1。ライセンス文は assets/fonts/OFL.txt、フォントを配る時は一緒に）は**システムフォントとして入れる**。ブラウザ側で FontFace を読み込む方式は、並列書き出しでタブが固まり時間切れになった。
- Gemini API の鍵：Claude Code のクラウド環境では通信の中継（プロキシ）が足す。手元の PC などでは環境変数 `GEMINI_API_KEY` に入れる（`scripts/_gemini.py` が googleapis.com 宛てにだけ付ける）。どちらでも鍵を表示しない・ファイルに書かない。402 が返ったら残高切れなので、ユーザーに補充を頼む。手元でできる工程（スロー・合成・音・書き出し）は止めずに進める。
- 書き出し用のブラウザは `scripts/browser.mjs` が探す（`REMOTION_BROWSER`、無ければ /opt/pw-browsers の Chrome Headless Shell）。
- Remotion の書き出しは、バンドルを `work/bundle` に固定する（ひな形は対応済み）。既定の /tmp だと毎回 public フォルダごと複製され、ディスクの割り当てを使い切った（ERR_INSUFFICIENT_RESOURCES）。`df` の Avail が 0 なら /tmp/remotion-webpack-bundle-* を消す。

## 1. 参照動画を分析する

この環境から YouTube には接続できないので、**Gemini に URL を渡して見て・聴いてもらう**。長い動画は一度に送ると中継で 502 になるため、80秒ごとの区間に分けて全カットを書き出させ、音は別に「音だけに集中」させて全編を1回。

- 取り出すもの：尺、カット数と平均の長さ、カメラ（固定か）、つなぎ、字幕の有無、音（BGM の有無、環境音の種類、声）、時間の流れ（昼→夕など）、終わり方（ロゴ・あいさつ）、繰り返しのモチーフ
- AI の読み取りは間違うことがある（看板の文字、BGM の有無は判定が揺れた）。根拠の具体的な方を採り、未確認は未確認と書く
- 結果は `docs/ref_<動画ID>/` に生の JSON とカット表を保存し、`docs/analysis.md` にまとめる（実例：assets/examples/analysis_example.md）

**真似るのは型、写さないのは固有のもの。** 元チャンネルの名前・ロゴ・決め台詞（例「存在しないのに懐かしい」）・実在の店名・固有の場面は使わない。決め台詞は言い換える（例「まだ来ない未来なのに、懐かしい。」）。実在のチェーン店（牛丼屋・コンビニ・喫茶店など）を残したいと言われたら、店名・ロゴ・看板の形はそのまま使わず、色と雰囲気で思い出せるオリジナルの店にする（例：オレンジの看板の牛丼「つぎ家」）。商品（おもちゃ・カードゲーム）も同じ。ドラマなど他作品の「世界線」を求められたら、固有名詞・人物・ロゴ・音楽・俳優の顔は使わず、雰囲気だけのオリジナルの場面にし、公開文にも作品名を入れない（理由をユーザーに一言で伝える）。

## 2. 世界観・テーマ・構成表

`docs/theme.md` に、作品の顔（題・副題・ログライン・尺・音の版）、世界設定、共存などの「約束」、構成表（カットごとの時刻・章・場面・原画・動き・文字）、音の設計、概要欄の文案を書く。
構成は**一日の流れ**（夜明け→朝→昼→夕暮れ→夜→深夜）を章にし、章の頭に縦書きの章題（漢数字＋時刻）。字幕は短い一文（体言止め・説明しすぎない）。最後は象徴的な景色＋題＋あいさつ（＋次回予告）。

**ドラマにしない。** 見る人が取り込まれて、自分で推察する作品にする（ユーザーからの強い要望）。
- 物語は、画面の中の物（カードの年、日記の日付、柱の傷、写真、手紙）と、今と昔を同じ構図でくり返すことで伝える。いきさつや気持ちを字幕で説明しない
- せりふはほとんど入れない。人の声は遠くの聞き取れないざわめき程度、ロボットは「ピ。」だけ。字幕のせりふは、シリーズでくり返す一行（「来年も、いっしょに見ようね。」）程度まで
- 字幕は日付と、町のことを書いた短い文だけ（1章で15〜25行）。顔と表情で泣かせない。音楽で盛り上げすぎない
- 台本には「見る人が推察する手がかり」の表（気づいてほしいこと／それを伝える画面の中の物）と、「画面では語らない裏設定」を分けて書く（実例：第二章の台本 `videos/ai-human-coexistence/docs/chapter2_script.md`）

## 3〜4. 原画と動き

- 原画は `assets/gen/prompts.json` に**共通ブロック**（世界・ロボットの統一デザイン・写真の質感・人物は小さく後ろ姿・指定した看板以外は文字なし）と**場面ごとの指示**を書き、`gen_image.py <ID> --refs 既存の採用画像2枚` で生成。参照画像を渡すと世界の見た目がそろう。
- 生成したら必ず目で見る：看板の文字化け、ロボットのデザインの揺れ、余計な文字。直しは `edit_image.py`。
- Veo は1カット8秒。`assets/veo/prompts.json` にカットごとの原画（採用した版まで、例 `N02_v2`）と指示文を書き、`veo_batch.py` で4並列。指示文は「Locked-off static camera.（または Very slow push-in）＋動くもの＋共通の締め（文字や形を変えない、音楽・声なし）」。Lite は negativePrompt を受け付けない。
- 「他社のコンテンツ」で弾かれたら、似ていると判断されそうな要素（ロボットの形、実在のチェーンに似た看板の配色）を原画の側で描き替えて再生成。看板の色は `recolor_region.py` で手元で塗り替えられる。
- 物語を伝える紙（カード・日記・お守り）は、原画と Veo では**白紙のまま**にして、字は後から焼き込む（references/in-frame-text.md）。AI は日本語の字を正しく書けない。
- 残高切れ（402）で作れなかったカットは、原画の静止画にゆっくり寄るクリップで仮に組み、動きに合わせる音（電車の通過など）は外しておく。補充したら作り直す。
- 生成後は全カットを数コマずつ並べて確認：形の崩れ（ロボットの頭、飛行車）、人物の増殖、画面に現れる偽の文字。

## 5〜6. スローと合成

- `slowmo.sh <ID> <元動画> [頭を切る秒] [倍率] [使う長さ]`：動き補間で 24→60fps にしてから半速 30fps（16秒）。1本 7〜10分、4並列（`scripts/slowqueue.sh`）。音は rubberband（crisp 設定）で半速。Veo の頭や後ろが崩れたカット（顔がこちらを向く、形が変わる）は、使える所だけを倍率を上げて伸ばし、`sync_cliplen.py` で timeline に長さを書く。
- 合成は `src/timeline.json` だけで決まる（尺・字幕・章題・題・空中電子版・音の割り当て）。書式は references/timeline.md。
- 空中電子版は `track.py` でカメラの動きを追跡して景色に貼りつける（Veo は「固定」と頼んでも動く）。置き場所は**見せ場（飛行車、開く扉）を隠さない空の部分**。`track_check.py` で確認。
- 画面の中の実物の板（掲示板・黒板）に文字を出すときは、`fixed`（揺れない）＋`opaque`（下を隠す）で板に合わせる。Veo が板に偽の文字を描くことがあるので、その範囲を覆う。手が板に触れる場面では、手の位置を覆わない。
- 文字の見え方は `node scripts/stills.mjs <ID>:<秒>` で静止画にして必ず確認：看板と章題の重なり、明るい空の上の白文字（薄い影を敷く）、枠からのはみ出し。

## 7. 音

- **環境音のみ版が基本**（元チャンネルの型）。Veo の現場音を半速に伸ばしたもの＋合成した環境音（波・蝉・ヒグラシ・鈴虫・雨だれ・風・遠いざわめき）＋効果音（霧笛・五時のチャイム・電子版の音・はんこ・チョーク）。
- Veo の音に**頼んでいない音楽**が入ることがある。必ず確認（Gemini の試聴、使えなければスペクトログラムで「音程が段々に変わる持続音」を探す）し、入っていたらそのカットは Veo の音を使わない。
- テーマ曲は `compose.py`（作曲→FluidSynth）。timeline.json の章（序・一〜五・結）の頭で入り、章ごとに編成を変え、祭りの場面は休む。章ごとの音量差は build_theme.py がならす。
- 終わりのあいさつは `tts_outro.py` で4声作って聞き比べ、選んだものを `audio/src/outro/closing.wav` に（地名はひらがな）。
- 仕上げ：テーマ曲版 -14 LUFS、環境音版 -16 LUFS、先読みリミッターでトゥルーピーク -1 dBTP 以下（AAC にした後で測る）。
- 私（Claude）は音を聞けない。抜粋を `audio_qa.py` で Gemini に聴かせ、判定のぶれも考えて、同じ所が2回悪ければ直す。最後は人の耳で確かめてもらうよう伝える。

## 8〜10. 書き出し・点検・納品

- `node scripts/render_shots.mjs`（カットごと、済んだものは飛ばす）→ `python3 -I scripts/assemble.py --crf 21 --maxrate 10M --preset medium --preview`（→ `out/<slug>_theme.mp4`・`out/<slug>_asmr.mp4`）。カットごとにしておくと、場面を足しても他を書き出し直さずに済む。
- 点検：`qa_final.py`（形式、黒コマ・止まったコマ、8秒ごとの一覧画像を全部見る）、`ebur128` で音量とトゥルーピーク。
- 納品：
  - 会話への添付は **30MiB まで**。480p の2パス（映像 440k＋音声 96k）で 6〜7分が約27MB
  - 高画質は上映ページ：`make_screening.py` → 一覧を4回前後に分けて Artifact に公開（.m3u8/.ts は配信できないので分割 MP4 と .txt の目次、hls.js で再生）。詳しくは references/delivery.md
  - Veo の元動画（有料）はリポジトリに保存してよいか確認して保存（作り直しに必要）。大きな生成物（スロー・書き出し）は保存しない
- 概要欄には AI 生成である旨と架空である旨、YouTube の「改変または合成されたコンテンツ」を「はい」にするよう添える。

## 落とし穴（詳しくは references/pitfalls.md）

- Remotion のバンドルが /tmp を埋める → 置き場所を固定、終わったら消す
- フォントはシステムに入れる（ブラウザ読み込みは並列書き出しで固まる）
- Gemini TTS は前置きの英語の指示まで読み上げる → 指示を付けない／最初の無音まで切る。地名はひらがなで
- 字幕の一文字ずつのぼかし（CSS filter）や全画面の合成は書き出しを数倍遅くする → ぼかしは出現中だけ、フィルムの質感は ffmpeg でかける
- `pkill -f <名前>`・`pgrep -f <名前>` は自分のコマンドにも一致する（自分のシェルを殺す、待ちのループが終わらない）→ `^` で始まりを固定するか、PID・ログ・出力ファイルで判定する
- 長い待ちは `sleep` で繋がず、終わりを検知するバックグラウンドの待機を使う
