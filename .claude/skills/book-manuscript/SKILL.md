# 書籍の原稿づくり

長い原稿は、章ごとに分けて並列に書き、最後に全体をそろえる。全体の読み通しは、コンテキストの大きい Gemini に任せると速い。

## 手順

1. **企画**: 読者・読み終えたときに得られること・分量（字数）・締め切りを決める。
2. **章立て**: `planner` で章と節の構成を作り、各章で言うことを1〜2文で書く。`jeb-judge` に plan として判定させる。
3. **用語集と表記ルール**: 先に `ai-ecosystem/output/<書名>/glossary.md` を作る（固有名詞・カタカナ語・数字の書き方）。各章の担当はこれに従う。
4. **章ごとに執筆**（並列）: 章ごとにサブエージェントへ「章の目的・前後の章の要旨・用語集」を渡して書かせる。事実には出典を付ける。
5. **全体の読み通し**: 全章をつなげ、`ask-other-ai` で Gemini に「章どうしの重複・矛盾・話の飛び」を挙げてもらう。指摘を反映する。
6. **推敲**: `japanese-polish` で章ごとに直す。
7. **図**: 必要な図は `ask-other-ai`（Codex）か HTML で作り、`judge-image.mjs` で確認する。
8. **体裁**: Markdown から PDF / EPUB に書き出す（pandoc がある場合の例）。
   ```bash
   pandoc ai-ecosystem/output/<書名>/*.md -o ai-ecosystem/output/<書名>/book.epub --toc
   ```
9. **検品**: `quality-inspector` で目次・リンク・図の表示を確認し、最後に `jeb-judge`。出版・販売サイトへの登録は人間が行う。

## 注意

- 他人の文章・図を引用するときは、引用の範囲と出典を明記する。長い転載はしない。
- 原稿は `ai-ecosystem/output/`（Git 管理外）に置く。公開リポジトリに未発表の原稿を入れない。
